## Goal

The gift becomes installable — through four doors, from one artifact. Three deliverables: (1) the **F-Droid eligibility checklist run as a release gate** — FLOSS-everything, the analytics/ads/backend/crash-SDK allow-list (the existing `tool/check_dep_allowlist.sh`, now proven against a deliberate violation), and **zero Anti-Features**: no NonFreeNet (core muṣḥaf bundled, only optional one-time static downloads), no NonFreeAssets (font/audio license terms verified for redistribution + derivatives before any pack ships), no Tracking, no Ads — recorded green as a committed artifact; (2) **`fastlane/metadata/android/{ar,fa,ckb}/` populated** (no `fastlane/` dir exists yet) — `short_description.txt` (≤80 chars), `full_description.txt` (≤4000 chars), `images/` (icon + per-locale screenshots) — the **single in-repo source of truth** that auto-syncs to F-Droid, feeds Play via `fastlane supply`, and grounds the App-Review business-model note; a new `tool/check_store_metadata.sh` gate keeps it complete; (3) the **four-channel release executed** — F-Droid (primary), Google Play, Apple App Store, signed GitHub Releases for Obtainium — all from E20-T02's ONE signed, SLSA-attested tag, `gh attestation verify` green against the published bytes. Producing the signed AAB and the gate re-run is T02 (consumed here); the privacy declarations and policy link are T05 (this task writes **listings**, it never re-declares privacy); the trust pack/REUSE/DCO is T04; the verify-yourself doc is T07. No monetization artifact appears on any channel.

## Implementation notes

Repo reality: `release.yml` exists (tag-triggered, pinned Flutter `3.41.2`, gate re-run; T02 completes its build/sign/attest steps); `ci.yml`'s `restraint` job is where `tool/` gates run; `tool/check_dep_allowlist.sh` already enforces the allow-list + banned-SDK regex; `tool/test/*.sh`/`*_test.dart` is the gate-test convention. This task **extends** those — it duplicates no gate and re-litigates no decision.

1. **Files.** `fastlane/metadata/android/{ar,fa,ckb}/short_description.txt` + `full_description.txt` + `images/icon.png` + `images/phoneScreenshots/*.png`; `docs/release/app-review-note.md` (the business-model note, verbatim from 13-oss §7); `docs/release/fdroid-eligibility.md` (the recorded checklist); `tool/check_store_metadata.sh` + `tool/test/check_store_metadata_test.sh`; `tool/test/check_dep_allowlist_test.sh` (net-new — the allow-list gate currently has no negative-proof test). All new text files carry SPDX headers; images get a `.reuse/dep5` stanza (T04's conventions).
2. **The eligibility checklist is evidence, not prose.** `docs/release/fdroid-eligibility.md` reproduces the 13-oss §5 table with one evidence pointer per row: FLOSS-everything → `reuse lint` (T04) + the dep allow-list; no banned SDK → `check_dep_allowlist.sh` (its `banned_regex` already covers firebase/crashlytics/sentry/analytics/ads); no NonFreeNet → core bundled (PRD §21 amendment) + the T03 airplane-mode acceptance run; no NonFreeAssets → the KFGQPC font terms verification recorded, and a standing block: **no reciter/audio pack ships while PRD §21 open decision 4's license is unresolved**; no Tracking/Ads → T05's zero-collection posture, no ad SDK in the graph; reproducible our-key build → T02's `release.yml` + attestation; localized listing → this task's `fastlane/` tree. Each row is checked ☑ with a link, or the release does not proceed.
3. **Prove the allow-list gate rejects a tracker** (eng-add-ci-check: prove against a deliberate violation). `tool/test/check_dep_allowlist_test.sh` copies the manifests to a temp tree, injects `firebase_analytics:` into a pubspec, runs the gate against the copy, and asserts non-zero exit; a second case injects an innocuous but **off-list** package and asserts it also fails (it is an allow-list, not a ban-list). Never mutate the real manifests.
4. **`tool/check_store_metadata.sh` — the listing-completeness gate.** For each locale in exactly `{ar,fa,ckb}`: both description files exist, non-empty, UTF-8; `short_description.txt` ≤ 80 **characters** and `full_description.txt` ≤ 4000 characters — count characters (`wc -m` under a UTF-8 locale), never bytes: Arabic script is multibyte and a byte count would silently allow an over-limit listing; `images/icon.png` exists; ≥1 screenshot in `images/phoneScreenshots/`; the three locales carry the **same file set** (no locale silently missing a screenshot). Fails loud on the first violation; wired into `ci.yml`'s `restraint` job **and** `release.yml` (before publish); registered in T01's gate→job mapping.
5. **The descriptions are transcreated adab surfaces.** Draft in Arabic (the base content language), transcreate fa and ckb — never machine-literal. Mandatory content: what the app is (revision companion for ḥuffāẓ, all 30 juz), the riwāyah named, free *ṣadaqah jāriyah* (no ads, no account, no purchase), the C-048 sentence (offline, no voice recording, nothing sent anywhere), open source + GPL. Forbidden: gamification vocabulary, guilt/fear/loss hooks, efficacy numbers or "science proves" phrasing (nothing registered supports it), any implied scholarly endorsement (open decision 5), "never forget"/"guaranteed retention" over-claims, exclamation marks/emoji. Extend `tool/check_adab_lint.dart` to accept the `fastlane/metadata/android/**/*_description.txt` files as plain-text inputs (it already takes file args; add a `.txt` branch beside the ARB parser) so the never-ship lint covers listings machine-side; the human per-locale review is still recorded, and **ckb is flagged pending native-speaker review** (PRD §21 remaining decision 1) before publish.
6. **Screenshots show the truth.** Real app renders per locale (RTL chrome, locale numerals), taken from the shipping build — never mocked features, never a decorated or re-typeset muṣḥaf crop (R1: the glyph layer in a screenshot is still the glyph layer), never a fabricated retention chart. One consistent set of surfaces across the three locales.
7. **The App-Review note** (`docs/release/app-review-note.md`) states the 13-oss §7 text: free, built as ongoing charity, no IAP/subscription/account/ads/data collection; the Quran is bundled; optional reciter audio is a one-time download of **static public data, not code** (Guideline 2.5.2); the engine is plain compiled Dart arithmetic, no AI model. It must agree with T05's declarations word-for-word on posture — reference, don't re-declare.
8. **Execute the four channels from the one tag.** (a) **F-Droid (primary):** submit the fdroiddata build recipe (reproducible, our signing key, metadata auto-synced from `fastlane/`); (b) **Google Play:** `fastlane supply` pushes the same metadata tree; T02's signed AAB is uploaded — the release job never rebuilds; (c) **Apple App Store:** the same tag's source, the privacy posture from T05, the business-model note attached; (d) **signed GitHub Releases:** T02's reproducible APK + its SLSA attestation attached to the tag's Release for Obtainium; run `gh attestation verify` against the **published** artifact and record the output in the eligibility doc. Same bytes to every Android channel; no channel ever gets a hand-patched binary.
9. **Pitfalls:** hand-editing a store console (the repo tree is the only source of truth — console edits are drift); byte-counting the length limits; framing any optional download as a runtime service dependency (NonFreeNet); shipping an audio pack with unverified terms (NonFreeAssets, open decision 4); a listing sentence that quietly originates a claim; a cheerful gamified register ("crush your revision!"); `continue-on-error` on any new step; publishing from a branch or moving ref instead of the immutable `v*.*.*` tag; forgetting T01's mapping registration for the two new checks.

- [ ] `tool/test/check_dep_allowlist_test.sh` proves the allow-list gate exits non-zero on an injected `firebase_analytics` dependency **and** on an off-list package, without touching the real manifests.
- [ ] `docs/release/fdroid-eligibility.md` records every 13-oss §5 row green with an evidence link; no NonFreeNet/NonFreeAssets/Tracking/Ads anti-feature; the reciter-audio row explicitly blocks any pack until PRD §21 open decision 4's license is verified.

- [ ] The four-channel release is executed from T02's one signed, attested tag — F-Droid recipe submitted (reproducible, our key), Play fed by `fastlane supply` from the same tree, App Store submission with the note, signed GitHub Release carrying the APK + attestation — and `gh attestation verify` succeeds against the published artifact, output recorded.
- [ ] No monetization artifact (IAP, subscription, ad SDK, paid tier) exists on any channel; no store console field diverges from the repo tree.

## Tests

All gate tests are deterministic, offline, and run against fixture copies — never the live manifests or a network socket (eng-write-dart-test conventions for the Dart pieces; `tool/test/*.sh` conventions for the shell gates). Written before the listings are finalized.

- `tool/test/check_store_metadata_test.sh` — green on a valid fixture tree; red on: a missing locale dir, an 81-character `short_description.txt` **written in Arabic script** (pins character-vs-byte counting), a 4001-character full description, a missing icon, an empty `phoneScreenshots/`, and a locale whose file set drifts from its siblings.
- `tool/test/check_dep_allowlist_test.sh` — the injected-tracker proof (firebase_analytics → non-zero exit) and the off-list-package proof, both against temp copies; pins that the gate is an allow-list.
- `tool/test/check_adab_lint_test.dart` (extended) — a fixture `full_description.txt` containing a never-ship phrase (streak/guilt/over-claim) and an exclamation mark fails the lint; the real listing files pass in all three locales.
- Release-run verification (recorded, not simulated): on the tagged release, `gh attestation verify` against the published AAB/APK succeeds and the eligibility checklist is committed green — both captured in `docs/release/fdroid-eligibility.md` as the auditable record.
