## Goal

Complete the repository trust pack that turns "no data leaves the device" into a *checkable* claim, and gate it. Most of the pack **already exists — extend it, never recreate it**: `LICENSE` (GPL-3.0 text + the §7 App Store additional permission), `LICENSING.md`, `CONTRIBUTING.md` (DCO 1.1 verbatim + sign-off instructions), `LICENSES/{GPL-3.0-or-later,OFL-1.1}.txt`, a comprehensive `.reuse/dep5`, and `fsfe/reuse-action@v6` running in ci.yml's `restraint` job and in release.yml. This task adds the three missing pieces: (1) **`SECURITY.md`** — private-disclosure contact, scope honestly limited to the asset-integrity gate + the dependency tree, no bounty promised; (2) **`PRIVACY.md`** — the in-repo privacy policy whose headline assertion traces to **C-048**, later *linked* (not written) by E20-T05 from both stores and in-app Settings; (3) the **net-new DCO sign-off CI check** (`dco.yml` — none exists today) failing any commit without a valid `Signed-off-by`. It also verifies/repairs **REUSE completeness** over the whole tree and pins the **§7 exception's presence in `LICENSE` with a machine check**, so the exception can never silently vanish before an outside contribution merges. No screen, no string, no claim is originated here — the epic originates nothing.

## Implementation notes

This task ships repo documents and CI metadata only: no Dart in `app/`/`packages/`, no screen, no ARB key, no engine or store change. The two new documents are trust surfaces read by huffaz, teachers, and auditors — their register is the adab voice gate (honest, calm, never over-claiming), and their facts are PRD §17 + C-048, nothing more.

1. **Inventory first, then extend.** Diff the docs-13 §2 trust-pack layout against the repo root. Do **not** rewrite `LICENSE`, the `CONTRIBUTING.md` DCO text, `LICENSING.md`, or existing `.reuse/dep5` stanzas — every changed line must trace to this task (surgical-changes rule). `CONTRIBUTING.md` may gain at most a one-line pointer to the new CI enforcement ("CI verifies the sign-off on every commit").
2. **`SECURITY.md`** (repo root, with the HTML-comment SPDX header used by `CONTRIBUTING.md`): a private-disclosure contact (email; no public-issue disclosure for vulnerabilities); the honest scope — there is no server, so the realistic surface is **the asset-pack integrity gate** (fail-closed SHA-256 verification) **and the dependency tree**; an explicit best-effort response expectation and an explicit **no-bounty** statement (13 §2 pitfall); a note that the highest-value report is one against the integrity gate or a dependency. No CVE-program theater, no over-promise.
3. **`PRIVACY.md`** (repo root, same SPDX header style): states what the app is (free *ṣadaqah jāriyah*, open source), then only PRD §17 facts — no account, no PII, no telemetry/analytics/ads, no microphone ever, the single network use (one-time download of static public, checksum-verified asset packs from the public GitHub repo, carrying no per-user data), all data on-device, backups user-initiated local files. Its headline sentence restates **C-048 verbatim-or-tighter, traced, never extended** — no new claim, number, or citation; where the reader could verify, point at the open repo (the T07 verify-yourself doc will deepen this — do not write those steps here). English is the document language; localized *store-facing* privacy text is T05/T06's concern, not a fa/ckb/ar ARB surface.
4. **The DCO gate — net-new `.github/workflows/dco.yml`** (no such workflow exists): `on: pull_request`, minimal permissions, `tim-actions/dco@v1.1.0` per docs 13 §3 — fails the PR if **any** commit lacks a valid `Signed-off-by` trailer matching the author. No Flutter toolchain needed (metadata-only job — do not drag in the 3.41.2 setup). No `continue-on-error`. Remediation is documented in `CONTRIBUTING.md` already (`git commit --signoff` / rebase to add) — never waved through.
5. **The §7 exception + trust-pack machine check — `tool/check_trust_pack.sh`** (SPDX header, matching the existing `check_*.sh` conventions): fails unless (a) `LICENSE` contains the exact exception marker `--- Additional permission under GNU GPL version 3 section 7 ---` **and** its "(2) you do not remove or alter this additional permission" clause, (b) `SECURITY.md`, `PRIVACY.md`, `LICENSING.md`, `CONTRIBUTING.md` exist and are non-empty, and (c) `CONTRIBUTING.md` still contains the "Developer Certificate of Origin" / "Version 1.1" lines. Wire it into ci.yml's `restraint` job beside the other `check_*` steps.
6. **Register both new checks in the T01 mapping** (the promoted gate→job table and ci.yml's comment block): the DCO check and `check_trust_pack.sh` as license-clarity/trust rows alongside `reuse lint` — an unmapped green check is a bug per T01's discipline. Do not renumber or reshape the PRD §20 gates.
7. **REUSE completeness pass:** run `reuse lint` locally (e.g. `pipx run reuse lint`) over the tree; the three new files carry `SPDX-FileCopyrightText: 2026 Zakaria Fatahi and Hifz Companion contributors` + `SPDX-License-Identifier: GPL-3.0-or-later` inline (markdown = HTML comment; yml/sh = `#`). Extend `.reuse/dep5` **only** if a genuinely new header-incapable file class appears — the existing bulk stanzas already cover binaries, fonts, ARB, and generated Dart. `reuse lint` stays release-blocking in both ci.yml and release.yml; touch neither step.
8. **The `LICENSES/CC-BY-4.0.txt` question — flag, don't add.** Docs 13 §2's layout lists `CC-BY-4.0.txt` "for any CC-BY docs/data vendored into the code repo"; today `LICENSES/` holds `OFL-1.1.txt` (Vazirmatn) instead, and the CC-BY mutashābihāt dataset lives in the *data* repo. Audit: if no CC-BY file is actually vendored into THIS repo, add nothing (REUSE wants texts only for licenses in use) and record the delta vs the EPIC deliverable line as an explicit note in the PR — never a silent pick either way.
9. **Dogfood the gate.** Every commit authored for this task itself carries a valid `Signed-off-by` trailer — the task's own PR is the DCO check's first real validation run, alongside the deliberate-violation proof below.
10. **Pitfalls:** rewriting the existing exception or DCO text (any edit to `LICENSE` beyond nothing is out of scope — the check *reads* it); promising a bounty, an SLA, or "unbreakable" security; letting `PRIVACY.md` drift into marketing or originate a claim/citation beyond C-048 + PRD §17; wiring the privacy-policy *link* anywhere (T05's); adding fastlane/store files (T06's); adding `CC-BY-4.0.txt` speculatively; a DCO job with `continue-on-error` or one that only checks the head commit; new dep5 wildcards that swallow future package source (per-file headers must stay in force there).

## Tests

All gates deterministic and offline (they read the repo tree only — no socket, no clock); each new check is proven against a deliberate violation per eng-add-ci-check before it counts.

- `tool/test/check_trust_pack_test.sh` (meta-test, mirroring `check_pipeline_wall_test.sh`): in a temp copy of the tree, the check passes on the real files; then (a) the §7 marker block stripped from `LICENSE` → non-zero exit, (b) `PRIVACY.md` deleted → non-zero exit, (c) the "Version 1.1" DCO line removed from `CONTRIBUTING.md` → non-zero exit. Wired into the `restraint` job's tool-gate step beside the existing meta-tests.
- **DCO deliberate-violation proof:** a scratch PR with one commit deliberately missing `Signed-off-by` shows the DCO check red (and green after `git rebase --signoff`); the run link is recorded in this task's PR description. Every subsequent commit on the branch carries a valid sign-off.
- **REUSE proof:** `reuse lint` green in CI on the branch (the three new files included); a local run with one SPDX header deliberately removed from `SECURITY.md` shown to fail before restoring it.
- **Mapping-registration pin:** a grep proves ci.yml's gate→job mapping block (and the T01-promoted table) names both new checks — the DCO row and the trust-pack/§7 row — so neither is an orphan green check.
- **Adab register review (recorded):** both documents read against the never-ship phrase list (no guilt/fear/loss, no over-claim, no `!`); the recorded pass feeds the E20-T08 conscience checkpoint.
- **No-drift pin:** `git diff` on `LICENSE` is empty in the final PR — the exception is verified by the check, never re-authored.
