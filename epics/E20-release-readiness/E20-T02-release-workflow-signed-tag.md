## Goal

Complete `.github/workflows/release.yml` so that pushing **one immutable version tag** (`v*.*.*`) re-runs the **entire** PRD §20 machine-gate suite at parity with `ci.yml`, then — and only if every gate is green — produces a **reproducible Android AAB signed with our own key** sourced exclusively from encrypted CI secrets, attests it with **SLSA build provenance** (`actions/attest-build-provenance@v1`, verifiable via `gh attestation verify`), and hands the artifact to E20-T06 for distribution. The workflow already exists with the right trigger, permissions, and `3.41.2` pin, but its gate re-run is a **subset** of `ci.yml` and its Build-signed-AAB + attest steps are commented `TODO (E20)` stubs — this task closes both gaps. The refusal-to-publish is **structural** (a terminal job that `needs` every gate job; a red *or skipped* gate means the build step never runs), never an `if:` bolted onto a `continue-on-error`. The binary ships **lean**: the pinned asset tag + manifest hashes only — the workflow never fetches Quran assets at app-build time. This task touches no product Dart, adds no screen, no string, no claim; it consumes E20-T01's canonical gate→job mapping as the parity oracle and does not edit `ci.yml`.

## Implementation notes

This task is release machinery only: no `lib/` change, no new gate *contract* (T01), no new tool gate script logic — it schedules what exists. Per eng-add-ci-check, every check it wires already maps to a named PRD §20 gate in T01's table.

1. **Files:** `.github/workflows/release.yml` (complete it); `app/android/app/build.gradle.kts` + `app/android/key.properties` handling (release signing config only — build configuration, not product code); `.gitignore` (add `key.properties`, `*.jks`, `*.keystore`); `tool/test/check_release_workflow_test.sh` (net-new meta-test, mirroring the existing `tool/test/*.sh` pattern). Do **not** touch `ci.yml`, any `tool/check_*` gate script, or any Dart under `lib/`.
2. **Shape: gate jobs + one needs-gated terminal job.** Restructure the single `release` job into mirrors of `ci.yml`'s five jobs — `fast`, `date-matrix` (the `TZ: Asia/Tehran | Pacific/Kiritimati | UTC` matrix), `golden`, `restraint`, `journeys` (the api-24 `reactivecircus/android-emulator-runner@v2` leg) — plus a terminal `build-sign-attest` job with `needs:` on **all five**. GitHub's `needs` semantics skip the dependent when any need fails *or is skipped*, so refuse-to-publish is structural. No `continue-on-error`, no `if: always()`/`if: failure()` anywhere in the file.
3. **Parity checklist — what the stub is missing (add all of it, commands copied verbatim from `ci.yml`; T01's mapping table is the oracle — every machine-checked row must appear in `release.yml`):**
   - *fast mirror:* `backup` added to the engine vector loop (the stub runs only engine/models/profiles); the unit+widget runs (`--exclude-tags golden --coverage`) over data/quran/l10n/features/assets + `app`; the generated-file lcov strip (`*.g.dart`, `*.drift.dart`, `*.freezed.dart`, `*/generated/*`) — coverage published, **never** gated;
   - *date-matrix mirror:* the three TZ legs (`Asia/Tehran`, `Pacific/Kiritimati`, `UTC`) running the engine date-correctness suite and the backup timezone-invariance suite (`--exclude-tags crypto`) — a TZ=UTC-only pass is never accepted;
   - *golden mirror:* already present in the stub (`packages/quran` + `packages/features` `--tags golden`) — keep verbatim, never `--update-goldens`;
   - *restraint mirror:* `check_engine_purity.sh`; `check_quran_isolation.sh`; `check_pipeline_wall.sh` + its meta-test; `check_token_discipline.dart` + its meta-test; the `check_l10n_complete_test.sh` meta-test; `check_claims_coverage.dart`; the five tool `package:test` suites (`verify_asset_integrity_test.dart`, `check_adab_lint_test.dart`, `check_ckb_canonical_test.dart`, `check_arb_plurals_test.dart`, `check_claims_coverage_test.dart`);
   - *journeys mirror:* the api-24 x86_64 emulator run of `app/integration_test` (T03's airplane-mode journey rides here once it lands).
4. **Toolchain pin on every job:** `subosito/flutter-action@v2`, `flutter-version: '3.41.2'`, `channel: stable` — MUST equal `ci.yml`'s `FLUTTER_VERSION` (reproducibility precondition *and* golden stability). The meta-test pins the equality so the two workflows cannot drift.
5. **Signing (build job only):** decode `KEYSTORE_BASE64` to a runner-temp `.jks`; write `app/android/key.properties` (`storeFile`, `keyAlias` ← `KEY_ALIAS`, `storePassword`/`keyPassword` ← `KEY_PASSWORD` — the doc names exactly these three secrets; a fourth would need a decision-log amendment). The Gradle signing block reads `key.properties` **if present** and falls back to debug signing locally, so dev builds are unchanged. Never `echo` a secret; the key lives only in encrypted CI secrets and one offline backup (13 §4 refusal).
6. **Build → attest → self-verify → hand off:** `flutter build appbundle --release` in `app/` from the tagged commit; `actions/attest-build-provenance@v1` with `subject-path: app/build/app/outputs/bundle/release/app-release.aab` (uses the already-declared `id-token`/`attestations: write`); then run `gh attestation verify <aab> --repo ${{ github.repository }}` in-workflow so a broken attestation refuses at tag time, not in an auditor's hands; upload the AAB + verification output via `actions/upload-artifact` for T06. The GitHub Release entry itself is T06.
7. **Reproducibility, concretely:** the build runs on the pinned Linux runner with the pinned Flutter and the repo's checked-in Gradle wrapper, from the immutable tagged commit — so an auditor re-running `flutter build appbundle --release` at the same tag with the same toolchain rebuilds the exact bytes; put the one-line rebuild recipe in a comment at the top of the build job (T07 turns it into `docs/verify-yourself.md` prose — do not write that doc here).
8. **Lean binary:** `release.yml` never invokes `tool/fetch_core_assets.sh` and opens no network fetch for Quran assets; whatever the binary bundles comes from the checked-out, hash-verified tree — `verify_asset_hashes.dart` (gate 1, currently dormant/fail-closed on the empty manifest) runs exactly as `ci.yml` runs it.
9. **LICENSE §7 guard:** one grep step asserts the "Additional permission under GNU GPL version 3 section 7" text is present in `LICENSE` before the build step (13 §1: the exception must exist before store distribution; the file is T04's — this is only a fail-closed guard).
10. **C1/C2 at the tag:** the re-run `check_dep_allowlist.sh` is the resolved-graph proof that no analytics/ads/backend/crash SDK and no ML/ASR package is linked; capture its release-run output in the dry-run record — do not write a new script for this.
11. **SPDX discipline:** `release.yml` keeps its existing REUSE header and the new `check_release_workflow_test.sh` carries one (`GPL-3.0-or-later`), is `shellcheck`-clean like its `tool/test/*.sh` siblings, and prints no user data (there is none — it reads workflow files only).
12. **Pitfalls:** re-running a subset "for speed" (refused — jobs parallelize, so full parity costs ~one `ci.yml` wall-time); any `--update-goldens`/`--update-vectors` in release (the gate would assert nothing); attesting before gates pass (attest lives only inside the needs-gated job); adding a `workflow_dispatch`/branch trigger (the trigger stays the immutable tag, never a moving ref); committing `key.properties` or a `.jks` "temporarily"; pinning to the docs' stale `3.38.0`; editing `ci.yml` under the parity banner (that is T01's file to keep canonical).

## Acceptance criteria

- [ ] `release.yml` re-runs the full T01-mapped machine suite at parity with `ci.yml`: every command in `ci.yml`'s five jobs (analyze, engine/models/profiles/backup vectors, unit+widget+coverage-strip, three TZ legs, goldens, all restraint scripts + meta-tests + tool `package:test` suites, claims coverage, asset hashes, REUSE, emulator journeys) appears in `release.yml`.
- [ ] The terminal `build-sign-attest` job `needs` every gate job; a red **or skipped** gate structurally prevents build, attestation, and artifact upload; `grep -rn continue-on-error .github/workflows/` returns nothing.
- [ ] Every `release.yml` job pins `subosito/flutter-action@v2` with `flutter-version: '3.41.2'` equal to `ci.yml`'s `FLUTTER_VERSION`, `channel: stable`.
- [ ] The AAB is built from the immutable tagged commit and signed only via `KEYSTORE_BASE64`/`KEY_ALIAS`/`KEY_PASSWORD` secrets; no `*.jks`, `*.keystore`, or `key.properties` is tracked by git; local debug builds still work with no keystore present.
- [ ] `actions/attest-build-provenance@v1` runs over the AAB and the in-workflow `gh attestation verify` step passes; AAB + attestation are uploaded as workflow artifacts for T06.
- [ ] `release.yml` performs no network fetch of Quran assets (no `fetch_core_assets.sh`, no asset URL); the `LICENSE` §7-exception grep guard runs before the build step.
- [ ] The dry-run is recorded: a scratch tag with one injected red gate produced **no** artifact and **no** attestation; a clean scratch tag produced a verified AAB; run URLs linked, scratch tags deleted.
- [ ] No product code changed: the diff touches only `release.yml`, the Android signing config, `.gitignore`, and the meta-test.

## Tests

All checks are deterministic and offline by construction — the workflow's only network use is GitHub's own actions/Sigstore plumbing, never a Quran-asset or telemetry socket. Per eng-add-ci-check, every gate is proven against a deliberate violation.

- `tool/test/check_release_workflow_test.sh` (net-new; runs as the first step of `release.yml`'s restraint mirror and locally via `bash`) — pins: (a) no `continue-on-error` in any workflow file; (b) `release.yml`'s `flutter-version` equals `ci.yml`'s `FLUTTER_VERSION`; (c) every gate command extracted from `ci.yml`'s five jobs is present in `release.yml` — if `ci.yml` later gains a check, the next tag fails closed until parity is restored; (d) the build job's `needs:` lists every gate job; (e) no `--update-goldens`/`--update-vectors` and no asset-fetch invocation in `release.yml`; (f) no tracked `*.jks`/`*.keystore`/`key.properties` anywhere in the repo; (g) the attest and `gh attestation verify` steps exist after the build step.
- **Recorded dry-run exercise** (one-time release evidence, not a committed test): push scratch tag `v0.0.1` from a branch carrying one deliberate violation (e.g. a temporarily mutated ARB value that trips the adab lint suite) → the restraint mirror goes red, `build-sign-attest` is skipped, zero artifacts; push clean scratch tag `v0.0.2` → signed AAB + green in-workflow `gh attestation verify`; capture both run URLs and the `check_dep_allowlist.sh` output (the C1/C2 graph proof); delete the scratch tags and runs' artifacts.
- Existing suites re-run unchanged and byte-identically (frozen engine vectors, real-font goldens on the pinned Linux runner, restraint scripts) — this task adds no product test, regenerates no golden master, and touches no vector.

- [ ] **Offline / no-network (gate 6):** the full three-layer gate re-runs at tag time (analyze banned-imports, dep allow-list, no-network script) plus the journeys leg; the release binary contains no second network client (C1, §19.3); the workflow itself fetches no Quran asset at app-build time.
- [ ] **No AI / no microphone:** the re-run dep allow-list proves no ML/ASR/analytics/ads/backend/crash SDK in the resolved graph (C2); the artifact is plain compiled Dart + static data — the 2.5.2 posture the App-Review note (T06) will claim is true by construction here.
- [ ] **Quran text fidelity (gates 1–2):** `verify_asset_hashes.dart` re-runs against the checked-out tree and the real-font muṣḥaf goldens re-run on the pinned Linux runner (never blessed in CI); a one-pixel diacritic drift refuses the release; the runtime fail-closed verifier is untouched (E05-owned).
- [ ] **Never "safe to drop" (gates 3–4):** the frozen golden vectors and `glados` invariants (trust clamp ≤ cycle ceiling, manzil never dropped, a lapse demotes, teacher overrides, no "safe to drop") re-run from the tag; a clamp violation blocks the ship, full stop.
- [ ] **No gamification / no shame:** this task adds zero user-facing strings, screens, or claims; the adab banned-phrase lint suite re-runs inside the release restraint mirror so no guilt/fear/streak copy can ride a tag out.
- [ ] **RTL + fa/ckb/ar (gate 5):** the full localization gate re-runs — l10n completeness + its meta-test, canonical-ckb and Arabic six-plural suites, and the per-locale RTL/numeral goldens on the real bundled fonts.
- [ ] **Accessibility:** no UI is added or changed; the E08 recorded pass is untouched, and the release fast-mirror re-runs the features widget suites (including the WCAG-contrast audit) exactly as `ci.yml` does.
- [ ] **Deterministic, auditable release:** pinned toolchain on every job (3.41.2 == ci.yml == README); publish is structurally impossible on a red or skipped gate; the signing key exists only in encrypted CI secrets + one offline backup; `gh attestation verify` binds artifact → source → workflow so an auditor can rebuild the exact bytes from the tag (feeds T07); coverage is published, never gated; gates 7–8 remain recorded **human** sign-offs (T08/T09) — a green run alone never means release-ready.
