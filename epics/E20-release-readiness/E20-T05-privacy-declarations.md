## Goal

Declare the **strongest truthful privacy posture on every store, and make "zero collection" machine-enforced**. Four deliverables: (1) the app-level Apple privacy manifest `app/ios/Runner/PrivacyInfo.xcprivacy` (the epic's `ios/Runner/…` path, relative to the Flutter app root `app/`) — `NSPrivacyTracking=false`, empty `NSPrivacyTrackingDomains`, empty `NSPrivacyCollectedDataTypes`, and accurate required-reason codes for the two API categories the app actually touches (UserDefaults → `CA92.1` for settings, DiskSpace → `E174.1` for pack/backup file IO); (2) the in-repo source of truth for the two store forms — Apple's "Data Not Collected" nutrition label and Play's unskippable "No data collected" Data-safety form — recorded question-by-question in `docs/release/privacy-declarations.md`, reviewed in PRs like code; (3) the **mandatory privacy-policy link** (Guideline 5.1.1(i) — required even for a no-data app) wired to E20-T04's `PRIVACY.md` in App Store Connect metadata, the Play listing, **and** in-app Settings (one About-section row — the only UI this task adds); (4) the **privacy-posture release check** (the docs 13 §4 gate-table row) — `tool/check_privacy_posture.dart` fails on any code path that transmits user data, on any manifest drift, on a bundled plugin whose own manifest declares collection, or on a policy-link mismatch. The declaration is honest by construction — the app genuinely never transmits (PRD §17, C1) — and the honesty itself is religious trust (R5): the store assertion "collects nothing / no mic / offline" **traces to C-048, never originated here**.

## Implementation notes

This task adds no screen and originates no claim: one manifest file, one declarations doc, one Settings row, one gate. The gate is written **test-first** (the meta-test proving each failure mode precedes the happy path).

1. **Files:** `app/ios/Runner/PrivacyInfo.xcprivacy` (new); `docs/release/privacy-declarations.md` (new; new `docs/release/` directory); the About-section row in `packages/features/lib/src/settings/settings_screen.dart` + ARB keys in `packages/l10n/lib/src/arb/app_{ar,fa,ckb}.arb`; `tool/check_privacy_posture.dart` + `tool/test/check_privacy_posture_test.dart`; one `restraint`-job step in `ci.yml`.
2. **The manifest, byte-for-byte per docs 13 §6:** `NSPrivacyTracking=false`; `NSPrivacyTrackingDomains` empty array; `NSPrivacyCollectedDataTypes` empty array; `NSPrivacyAccessedAPITypes` = exactly `NSPrivacyAccessedAPICategoryUserDefaults` → `CA92.1` and `NSPrivacyAccessedAPICategoryDiskSpace` → `E174.1`. Register the file in the Runner target's Copy Bundle Resources (`app/ios/Runner.xcodeproj/project.pbxproj`) — an unregistered manifest is silently ignored by Apple. Dart plugins declare their own required-reason APIs in their own bundled manifests; the app-level file covers only the app's own usage.
3. **`docs/release/privacy-declarations.md`** records, question-by-question: the Apple nutrition-label answer (**Data Not Collected**) with the "Collect = transmit off device" definition quoted from docs 13 §6; the Play Data-safety answers (**No data collected, no data shared**; the 2025 automated binary scan corroborates an empty declaration); the cross-store matrix including F-Droid (no Tracking/Ads anti-feature — the open source is the disclosure, gate owned by T06); the canonical `PRIVACY.md` URL (stated **once** here — every other occurrence must match it); and the C-048 trace for the "collects nothing / no mic / offline" assertion. Store consoles are *set from* this doc, never the reverse (§2 discipline).
4. **The Settings policy-link row:** one `MihrabCard` in the existing About `SettingsSection` (after the science row, same padding/`space.space4` idiom), title from a new ARB key (e.g. `settingsPrivacyPolicyTitle`), tap → `ref.read(sourceLinkLauncherProvider).open(<canonical URL>)` — the system browser, clearly leaving the app; a calm no-op offline (the boundary's contract; the policy also ships in-repo, nothing in-app fetches it). Keys transcreated fa/ckb/ar (ckb flagged pending native review), calm factual register — no "we protect you" marketing; RTL by geometry; ≥48dp; `Semantics` label + button role.
5. **`tool/check_privacy_posture.dart`** (gate 6; fail-closed, exit non-zero on first violation, precise `file:line` messages): **(a) transmit path** — invokes the existing layers `check_no_network.sh` + `check_dep_allowlist.sh` and fails if either fails (never re-implements their greps); **(b) manifest** — parses the plist XML strictly (malformed = fail) and asserts tracking false, tracking-domains empty, collected-types empty, and the reason-code set equals the pinned expected set `{UserDefaults: CA92.1, DiskSpace: E174.1}` — any new required-reason API use lands as a reviewed change to both the manifest and this pin, or the release blocks; also asserts the file is referenced in `project.pbxproj`; **(c) plugin audit** — enumerates the iOS Dart plugins from `app/.flutter-plugins-dependencies` (after `flutter pub get`), locates each plugin's own bundled `PrivacyInfo.xcprivacy`, and fails if any declares `NSPrivacyTracking=true` or a non-empty `NSPrivacyCollectedDataTypes`; a plugin shipping no manifest fails unless on a pinned, commented allowlist; **(d) link consistency** — asserts `PRIVACY.md` exists at the repo root (T04), and that the canonical URL in the declarations doc, the Settings-row constant, and the URL's repo-relative target all agree — **string/file checks only, never an HTTP fetch** (deterministic, offline CI).
6. **Wiring:** add the step to the `ci.yml` `restraint` job beside the other `tool/` gates and add its meta-test suite to the `tool/test` run; register exactly one row in T01's gate→job mapping (gate 6 — no orphan check). `release.yml` gains it via T02's parity re-run — out of scope here.
7. **Pitfalls:** editing a store console first and back-porting (the repo doc is the source of truth); a manifest that parses but isn't in Copy Bundle Resources; padding the manifest with reason codes for APIs the app doesn't use ("accurate" cuts both ways); re-implementing the no-network greps inside the posture check (compose, don't fork); an HTTP liveness probe for the policy link (non-deterministic, and a socket in CI); localizing or paraphrasing the C-048 assertion into new store wording (T06's job, against the registered claim); adding an account or upload "for backup" to simplify anything (docs 13 §6 refusal — backup stays a local file); `continue-on-error` anywhere on the gate.

## Tests

All deterministic and offline by construction — the gate and its tests open no socket; the meta-test discipline (prove the gate against a deliberate violation) follows the existing `tool/test/` suites.

- `tool/test/check_privacy_posture_test.dart` (package:test, **written first**) — in a temp fixture tree: happy path passes; an **injected transmitting call** (a scratch Dart file containing `HttpClient` inside a scanned `features` dir) fails via the composed no-network layer; each manifest mutation fails independently — `NSPrivacyTracking=true`, one entry in `NSPrivacyCollectedDataTypes`, a dropped `CA92.1`, an extra undeclared reason code, malformed XML, manifest missing from `project.pbxproj`; a fixture plugin manifest with a non-empty collected-types array fails; a fixture plugin with no manifest and no allowlist entry fails; a declarations-doc URL that differs from the Settings constant fails; a missing repo-root `PRIVACY.md` fails.
- `packages/features/test/settings/privacy_policy_row_test.dart` (widget) — the About section renders the policy row; tapping it hands **exactly the canonical URL** to a recording `SourceLinkLauncher` fake (provider override) and performs no navigation and no socket open; a `false` (offline) return is a calm no-op with no error surface; ≥48dp target, `Semantics` label + button role; renders under fa/ckb/ar with locale-correct RTL geometry.
- CI proof: the `restraint` job runs the check and the meta-suite; the suite runs under the throwing-`HttpOverrides` offline guard (eng-write-dart-test) proving the gate itself never transmits.
