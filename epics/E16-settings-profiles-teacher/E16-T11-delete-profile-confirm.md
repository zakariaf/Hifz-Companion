## Goal

Build the **delete-profile confirmation** — the honest gate in front of the one irreversible action the Profiles section offers. Because there is no server and no soft-delete, deleting a profile actually deletes it: the dialog therefore states the **concrete consequence in plain words** (this profile's memorization record — its cards, its `review_log` entries, its cycle settings — is removed from this device, permanently; nothing is recoverable elsewhere), never a bare "Are you sure?". The **safe choice (Cancel / keep the profile) is the visually-primary `FilledButton` and the default focus**, low in the thumb band; the destructive choice is a plainer secondary affordance one deliberate step away toward the top-start, using thumb-zone difficulty as a *natural* safety margin — an honest safeguard, audited against the five dark-pattern strategies, never an obstruction. On confirm, the delete routes through **exactly one call to T08's `ProfilesNotifier` delete mutation** (one transactional repository write, commit before republish); the dialog itself writes nothing. It is scoped to **one profile** and is explicitly distinct from the **all-data erase owned by E17** — in copy, in ARB keys, and in tests.

## Implementation notes

This task is one dialog and one wiring: no schema, no DAO, no notifier method of its own. It is **test-first on the write-path routing and the copy invariants** — those tests exist and fail before the dialog is fleshed out.

1. **Files** (`features` package, `lib/src/profiles/`, per eng-add-feature-module conventions): `widgets/delete_profile_confirm_dialog.dart` — a dumb `DeleteProfileConfirmDialog` composing the E10 destructive-confirm scaffolding leaf; it takes the profile's already-localized display name and one `Future<void> Function()` `onConfirmDelete`, holds no state, imports no DAO/engine, reads no clock. The wiring binds `onConfirmDelete` to T08's `ProfilesNotifier` delete mutation in the profiles feature's provider scope.
2. **Consequence copy states all three halves** (ui-destructive-confirm Pattern 1; 10-privacy §8): *what* is removed ("{name}'s record on this device — the pages being tracked, the review history, and the cycle settings"), *that it is permanent*, and *that nothing is recoverable elsewhere* (no account, no server copy). The profile's typed display name is interpolated into the sentence **FSI/PDI-isolated** (a user-typed name inside an fa/ckb/ar sentence is a mixed run). A bare "Are you sure?" — or any copy that hides irreversibility — is a defect.
3. **Cancel-primary, delete one deliberate step away** (10-privacy §9; 05-layout §5): Cancel ("Keep this profile"-shaped) is the visually-primary `FilledButton`, the default focus, and sits **low in the thumb band**; the destructive action is a plainer `TextButton`/`OutlinedButton` placed toward the **top-start** — never the brightest button, never default-focused, never disguised as the safe one, and never hidden or greyed into unreachability either.
4. **One gate, proportional to blast radius** (ui-destructive-confirm Pattern 3): a single-profile wipe gets exactly **one** consequence dialog — no "type the word", no hold-to-confirm, no second screen. Escalating past what defeats an accidental tap is friction-for-friction and fails the §11 obstruction audit.
5. **Distinct from E17's all-data erase — structurally**: the title and body name *the one profile*; no "all data" / "everything" / "erase the app" phrasing; the ARB keys (`profileDeleteTitle`, `profileDeleteConsequence`, `profileDeleteConfirm`, `profileDeleteCancel`-shaped) are distinct from any erase-all key, and a test pins that no erase-all string renders in this dialog's tree.
6. **On confirm: one call, one transaction, commit before republish** (04 §4; eng-create-riverpod-store): the confirm button invokes T08's delete mutation exactly once; that method's repository call opens one `db.transaction`, truly deletes the profile row and its scoped cards / `review_log` rows / cycle config (rows gone, no soft-delete flag — PRD §10.3's sanctioned exception), and commits before the notifier republishes. The dialog dismisses on the returned future; the profile list re-renders from the re-emitted stream. Cancel and barrier-dismiss invoke nothing and write nothing. A failed write surfaces a calm retry, never a silent swallow, never guilt.
7. **Successor selection is not this dialog's decision**: if the deleted profile is the active one, T08's notifier re-points `activeProfileProvider` inside its own contract and T09's switcher re-renders; this dialog neither picks nor names a successor.
8. **Completion is quiet** (06 §2, §4): no celebratory or "success" motion/haptic, no alarming red flourish; at most one `haptic.warning` when the dialog *presents* (paired with the warning state, never repeated); the destructive button uses plain role colors — there is no `color.semantic.danger` to reach for, by design. Reduce-motion (`MediaQuery.disableAnimations`) degrades the dialog transition to cross-fade/instant.
9. **Copy register** (11-voice §4, §6; domain-adab): understanding → honest fact → the user's choice, with the two options framed as equals the user owns; no "you'll lose your hifz", no "must/should/don't", no shaming the deletion (a teacher removing a departed student's profile is a normal, dignified act). Every string through the ARB pipeline in fa/ckb/ar (ckb per policy), transcreated not literally translated; banned-phrase lint over every new key.
10. **RTL + accessibility**: `EdgeInsetsDirectional`/`AlignmentDirectional` only; both buttons ≥48dp `touch.min`, ≥`space.2` apart; the visible `color.outline` focus ring sits on the **safe** action; `Semantics` announce the full consequence sentence and *which button is destructive* before either is activated; body at `type.body` (load-bearing text never below it), title at `type.title`; ckb's longer copy reflows within the same insets.
11. **Pitfalls to avoid:** a bare "Are you sure?"; making delete the filled/default/focused button; type-to-confirm or hold gates on a one-profile scope; any "all data" phrasing or shared ARB key with E17's erase; a soft-delete flag on `review_log` rows; the dialog calling a DAO or deciding the successor profile; a red alarm treatment or hue-only danger signalling; a success haptic/animation on completion; hardcoded `left`/`right`; an unisolated interpolated profile name; guilt copy in any locale.

## Tests

All deterministic and offline by construction: recording doubles, seeded fixtures, no clock, real bundled fonts for goldens. Test-first on the write-path routing and the copy invariants.

- `features/test/profiles/delete_profile_confirm_test.dart` (widget, **written first**) — a recording `ProfilesNotifier`/repository double proves: tapping confirm produces **exactly one** delete invocation and one transactional write (the recorder's event log pins commit strictly before republish, and shows the profile row + its scoped cards/`review_log`/config rows deleted, no soft-delete flag); tapping Cancel and barrier-dismissing invoke **zero** writes; Cancel is the `FilledButton` and holds default focus while the destructive button does not; both targets ≥48dp; a failing repository shows the calm retry with nothing republished.
- `features/test/profiles/delete_profile_copy_test.dart` (unit) — the consequence key exists in fa/ckb/ar ARB and names the concrete outcome (interpolated name, the record/review-history/settings, "this device", permanence, nothing-recoverable); no bare "are you sure" key; the dialog's keys are disjoint from every erase-all/E17 key; the banned-phrase lint (guilt/fear/loss, "you'll lose your hifz", mandate words, `!`, emoji) passes over every new value in all three locales.
- `features/test/profiles/delete_profile_semantics_test.dart` (widget) — the `Semantics` tree exposes the full localized consequence sentence and identifies the destructive button before activation; the visible focus ring renders on the safe action; the interpolated display name is bidi-isolated in the announced string.
- `features/test/profiles/delete_profile_confirm_golden_test.dart` (golden) — per-locale (fa/ckb/ar) RTL goldens on the real bundled fonts: cancel-primary layout with the destructive affordance at the top-start, ckb reflow without truncation; a reduce-motion variant pins the instant presentation.
- Offline guard: the suite runs under an `HttpOverrides` that fails any socket open (eng-write-dart-test) — opening, cancelling, and confirming the dialog make no network call. (The epic-wide consolidated goldens/guard live in E16-T12.)

- [ ] **No AI / no microphone**: nothing here records, infers, or recommends — no "are you sure you want to lose your progress?" retention nudge, no exit-intent inference; the gate is a static honest surface.
