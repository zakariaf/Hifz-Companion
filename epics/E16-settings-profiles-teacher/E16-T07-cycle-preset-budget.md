## Goal

The Cycle section of Settings gains its three controls: (1) the **cycle-preset picker** — five *named*, tradition-shaped single-select cards a teacher recognizes (**7-Manzil weekly khatm · 1 juz/day · ½ juz/day · 2 juz/day · Custom**), instantiated on the E16-T02 picker primitive; (2) the **Pure-cycle mode** toggle — one explicit flag framed as *fidelity* ("follow my cycle exactly, no reordering"), never as "disable smart features"; (3) the **daily-budget** control — a bounded minutes stepper, never an unbounded free field. Together they are the Settings-side surface that WRITES the already-defined `EngineConfig` / `cycle_config` fields (the cycle ceiling, near-window, new-lines/day, daily budget, pure-cycle flag) through the single write path, then lets the engine rebuild the day deterministically. This surface stores a choice and computes **nothing**: no `due_at`, no `target_R`, no D/S/R value ever appears in or is written by this picker, and no `Slider`/retention-dial exists anywhere in its tree (design principle 1). Custom reveals exactly **four bounded fields** (far-cycle length, near-window in juz, new-lines/day, daily budget). Selection is quiet — no praise, no score, no "completion %" (C-025 guard).

## Implementation notes

This task is a write-only settings surface over E04/E03 primitives: it maps a named choice to already-defined config fields, persists through one controller method, and lets the day rebuild. The no-slider / no-D-S-R / write-only invariants are pinned test-first before visuals.

1. **Files** (in the `features` umbrella package, `lib/src/settings/`, per eng-add-feature-module): `widgets/cycle_preset_picker.dart` (five named cards on the T02 primitive), `widgets/pure_cycle_toggle.dart`, `widgets/daily_budget_control.dart`, `widgets/custom_cycle_editor.dart` (revealed only when Custom is selected), and `cycle_config_controller.dart` — a Riverpod `Notifier` (eng-create-riverpod-store) exposing `selectPreset(CyclePreset)`, `setPureCycle(bool)`, `setDailyBudgetMinutes(int)`, `setCustomField(...)`. Views are dumb; every mutation goes through the controller.
2. **The preset → config mapping is a constant table, not a computation.** `selectPreset` writes `cycle_type` + the preset's named constants (7-Manzil → `far_cycle_days = 7`; 1 juz/day → `30`; ½ juz/day → `60`; 2 juz/day → `15`, per ui-cycle-preset-picker Pattern 2 / engine §6). Anything derived (e.g. `far_target_per_day`) is derived on the E04/E03 side — this surface never computes a value, a date, or a ceiling.
3. **NO Slider, NO dial, NO math surface.** No `Slider` widget exists in the tree (asserted by test); no `target_R`, retention %, D/S/R, `due_at`, or "advanced" pane renders or is written anywhere in this task. The presets are the whole interface (design principle 1; PRD §15.1).
4. **Pure-cycle is one flag, framed as fidelity.** The toggle flips exactly `pure_cycle_mode` and nothing else; copy is "follow my cycle exactly — no reordering" (C-014), never "turn off smart scheduling"/"basic mode". It uses the M3 switch with a `Semantics` toggle announcement ("Pure-cycle, on/off").
5. **Custom = exactly four bounded, labelled fields.** Far-cycle length (days), near-window (juz), new-lines/day, daily budget (minutes) — steppers/selects whose bounds mirror the schema `CHECK`s (engineering 05 §2) so no invalid value is even offerable; each maps 1:1 to one config field. No fifth field, no free text, no raw retention target.
6. **Daily budget is a bounded minutes control** (also reachable outside Custom — it applies to every preset), rendered in locale numerals via `numberFormatFor(locale)` with mixed runs FSI/PDI-isolated. It caps the day the engine builds; the honest overflow line on Today (E12-T04) deep-links back to this control.
7. **Single write path, then a deterministic rebuild.** Each controller method calls the one repository method for "edit cycle config" (engineering 04 §4): transactional commit **before** republish; the republished config provider causes the day-plan provider to re-run E04's `buildToday` with the new `EngineConfig` — same `(cards, config, today)` → the identical `DayPlan`, every time. The controller uses the injected `CalendarDate` clock; no `DateTime.now()`, no engine call from a widget.
8. **Selection is quiet.** Selected = M3 state layer + shape/text per the T02 primitive; no confetti, chime, badge, "optimal!" praise, or "you're behind" pressure; no preset is marked "recommended" (no inference, PRD §17). Switching presets is a factual change and the UI simply reflects it.
9. **Strings via the ARB pipeline, transcreated fa/ckb/ar** (eng-add-localized-string): every card name, description, toggle label, and field label is an `l10n.*` key (ckb pending native+scholar review); preset names use the regional term-set vocabulary; "7", "30-day", juz counts, and minutes render in the locale numeral set. Cycle-description copy carries only C-016/C-036/C-014 facts; if a tradeoff line ("a wider cycle is less daily work") or the ʿarḍa precedent ships, register C-008/C-039 first.
10. **RTL by geometry + accessibility:** `EdgeInsetsDirectional`/`AlignmentDirectional` only; cards are a `Semantics` radiogroup, each row ≥48dp `touch.min` with name + selected/not-selected value; the toggle and steppers announce label + value; visible focus ring (`color.outline`); states mirror correctly under RTL (07-components §6).
11. **Pitfalls to avoid:** computing a ceiling/`due_at`/derived target in the picker (it writes named constants and user-entered bounded values only); any `Slider`/dial; showing or logging a D/S/R or retention %; framing Pure-cycle as "off"/worse; an unbounded or fifth Custom field; mutating config from a View or calling the engine from a tap handler; republishing before the commit returns; a "recommended for you" preset; celebration or urgency copy on selection; copy implying a longer cycle means a page is "safe" to see less (never "safe to drop" — §7.12).

## Acceptance criteria

- [ ] `settings/widgets/cycle_preset_picker.dart`, `pure_cycle_toggle.dart`, `daily_budget_control.dart`, `custom_cycle_editor.dart`, and `cycle_config_controller.dart` exist in the `features` package; every widget is dumb and every mutation routes through one controller method into the single write path (verifiable by grep: no DAO import, no `DateTime.now()`, no engine import in the widgets).
- [ ] The picker renders exactly the five named cards of PRD §15.1 on the E16-T02 primitive as a single-select radiogroup; selecting one writes `cycle_type` + that preset's constant config fields (7-Manzil → 7 · 1 juz/day → 30 · ½ juz/day → 60 · 2 juz/day → 15) and **nothing else**.
- [ ] No `Slider` (or any dial/retention-target control) exists in the tree; no `due_at`, `target_R`, D/S/R, retention %, or "completion %" is written, rendered, or logged by any surface in this task (C-025 guard).
- [ ] The Pure-cycle toggle flips exactly `pure_cycle_mode`; its copy frames fidelity ("follow my cycle exactly, no reordering" — C-014), never a downgrade.
- [ ] Custom reveals exactly four bounded, labelled fields mapping 1:1 to `far_cycle_days` / `near_window_juz` / `new_lines_per_day` / `daily_budget_minutes`, with bounds mirroring the schema `CHECK`s — an out-of-bounds value cannot be entered.
- [ ] Every mutation persists transactionally **before** republishing, then triggers a `buildToday` rebuild that is deterministic (same inputs → the identical day plan).
- [ ] Selection/toggle feedback is quiet: M3 state layer + shape/text, no color-alone signal, no confetti/praise/urgency, no "recommended" preset.
- [ ] Every user-facing string is an `l10n.*` ARB key in fa/ckb/ar (ckb flagged pending review); numerals render in the locale set, bidi-isolated; layout is RTL by geometry (`EdgeInsetsDirectional`, no `left`/`right`).
- [ ] Each card/toggle/stepper is a ≥48dp labelled `Semantics` target (radiogroup membership, selected value, toggle state) with a visible focus ring.

## Tests

All deterministic, offline by construction, with seeded fixtures, a recording repository double, and the injected `CalendarDate` (never a real clock). The write-boundary and no-slider invariants are written first.

- `features/test/settings/cycle_preset_picker_test.dart` (widget) — **written first**: tapping each named card routes through `selectPreset` and the recording repository receives exactly `cycle_type` + that preset's constant fields (asserting the 7/30/60/15 map) and **no other write** — specifically no `due_at`, `target_R`, or any D/S/R value in any recorded write; asserts `find.byType(Slider)` finds nothing; asserts no rendered text matches a retention-%/completion-% pattern; asserts the radiogroup `Semantics` (name + selected value per card, ≥48dp).
- `features/test/settings/pure_cycle_toggle_test.dart` (widget) — toggling writes exactly one field (`pure_cycle_mode`) and leaves every other config field untouched (recording repo diff); the label is the fidelity string, not a "disable"/"basic" string; the toggle announces its state.
- `features/test/settings/custom_cycle_editor_test.dart` (widget) — Custom reveals exactly four fields; each stepper is clamped to the schema bounds (attempting to step past a bound is a no-op); each edit writes exactly its one 1:1 field through the controller.
- `features/test/settings/cycle_rebuild_determinism_test.dart` (unit/controller) — after a persisted config change, the day-plan provider re-runs `buildToday` with the new `EngineConfig`; rebuilding twice from identical `(cards, config, today)` fixtures yields the identical `DayPlan`; the repository commit is observed **before** the republished state (persist-before-republish ordering pinned via the recording double).
- `features/test/settings/cycle_preset_golden_test.dart` (golden) — per-locale (fa/ckb/ar) RTL goldens of the five cards (one selected), the Pure-cycle toggle, and the Custom editor, on real bundled fonts; ckb's longer labels reflow without truncation. (E16-T12 consolidates these into the epic-wide golden lane.)
- Offline guard: the suite runs under an `HttpOverrides` that fails any socket open (eng-write-dart-test) — proves no preset selection, toggle, or budget edit opens a socket.
