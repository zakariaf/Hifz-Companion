## Goal

Instantiate the E16-T02 single-choice picker primitive **three times**, for the three pure-presentation preferences in the Settings **Display** section: **UI language** (fa / ckb / ar — all RTL), **theme** (light / sepia / dark), and **Quran font-size / zoom**. Each is a named radiogroup that persists exactly one preference through the single write path and re-renders the surfaces it affects: a language switch swaps the whole locale (the pinned `locale:` over the fixed `supportedLocales`, with direction *derived* from it), a theme switch re-tones the Mihrab token palette (each appearance is its own `ColorScheme` — tokens by name, never a hex), and the font-size/zoom choice is **stored for the E13 muṣḥaf reader to consume later** — this task applies nothing to the page. All three are presentation-only: none touches the schedule, a `due_at`, `EngineConfig`, or a single glyph of the sacred text. Per the epic's no-`Slider` gate, the zoom control is a **discrete named-step radiogroup, not a slider**. Nothing here celebrates, recommends, or phones home.

## Implementation notes

This task is presentation-only wiring over T02: three option-sets, three persisted preference fields, three controller methods. No engine call, no date math, no socket, no muṣḥaf glyph anywhere in its widget trees.

1. **Files** (in the `features` umbrella package, `lib/src/settings/`, per the T01 scaffold): `widgets/language_picker.dart`, `widgets/theme_picker.dart`, `widgets/quran_zoom_picker.dart` — each a dumb instantiation of the T02 primitive fed localized option data and a single controller callback (e.g. `setUiLanguage` / `setThemeAppearance` / `setQuranZoomStep` on the settings notifier). No new row anatomy; if a visual need isn't covered by T02, fix T02, don't fork it.
2. **Language option-set = exactly fa / ckb / ar** (PRD §13.1), each row labelled by its own **endonym in its own script** (ARB values — exact wording lands with the localization pass, never hardcoded); no flag icons, no "English", no Kurmanji. Selecting persists the locale code, then the app rebuilds with `MaterialApp.locale` pinned to it over the unchanged `supportedLocales` (eng 12 §1); the ckb row resolves `Locale.fromSubtags(languageCode: 'ckb')` (eng 12 §3). Default is *no pin* — device-locale resolution — until the user chooses.
3. **Direction is never touched by hand.** The switch changes the locale; `GlobalWidgetsLocalizations` derives RTL from it (eng 12 §2). All three locales are RTL, so the geometry holds across every switch — assert it, don't force it. The only permitted manual `Directionality` is the optional per-row language *preview* sample (eng 12 §2, island b).
4. **A language switch changes chrome only** (design 12 §8): buttons, labels, dates, numerals, term-sets re-render; the muṣḥaf page, its markers, and its fonts are untouched — the language picker imports nothing from the quran/rendering layer, which makes the violation structurally impossible (verifiable by grep).
5. **Theme option-set = light / sepia / dark** (PRD §15.2), each mapped to its named appearance whose `ColorScheme` and token values are owned by design 03 §3–§4; the picker persists the appearance name and the theme layer re-tones every surface. Default follows the system for Light/Dark (03 §3). Reference `color.*`/`type.*` tokens **by name only** — no raw hex/px/ms in any file this task adds. Night stays an in-reader appearance (03 §3, E13) — do not add it here.
6. **Selected theme is never signalled by color alone**: each row carries the radio glyph + its text label (T02 already enforces shape+text); an optional small appearance swatch may accompany the label but never replaces it (07-components §6; WCAG SC 1.4.1).
7. **Quran font-size/zoom is a discrete named-step radiogroup — NOT a `Slider`** (epic no-`Slider` gate; ui-settings-picker Pattern 1). Persist an ordered enum-like step (e.g. default → largest, a short fixed set), not a free float; any step label that shows a magnitude (e.g. "۱۲۵٪") renders in locale numerals via E09's `numberFormatFor`, FSI/PDI-isolated. The value is **stored here, applied in E13** as a uniform transform of the rendered layer (PRD §11.2) — this picker renders **no muṣḥaf glyph, not even a preview**, and never re-typesets or reflows anything.
8. **Keep the two text-size systems separate** (design 04 §1/§7): this preference governs the *reader's* zoom only; chrome text keeps following the OS text-scale. No copy may conflate them ("app text size" is not what this row sets — the ARB `@description` for its label must say so for translators).
9. **Every selection goes through the single write path** (eng 04 §4): one named repository method per preference, one transaction, committed **before** the notifier republishes and the surfaces re-render. Whether these fields are per-profile or app-global follows the E03 schema as built — this task consumes the existing settings DAO/repository surface and adds no schema.
10. **Pitfalls to avoid:** a `Slider` or stepper-with-free-value for zoom; hardcoding `Directionality(TextDirection.rtl)` anywhere; a glyph preview in the zoom or language rows; re-tonering by inline hex instead of the named appearance's scheme; a "recommended" tag, praise, haptic fanfare, or confetti on switch; an unregistered legibility/eye-strain claim in a subtitle; writing a preference from the View; touching `EngineConfig`, a `due_at`, or the stored instant; adding a fourth language or a Night row.

## Acceptance criteria

- [ ] `settings/widgets/language_picker.dart`, `theme_picker.dart`, `quran_zoom_picker.dart` exist in the `features` package; each instantiates the E16-T02 primitive (no duplicated row/radiogroup anatomy) and contains no engine call, no `DateTime.now()`, no quran/rendering-layer import (verifiable by grep).
- [ ] The language picker offers exactly fa / ckb / ar (endonym-labelled ARB strings, no flags, no Kurmanji); selecting persists the locale through one controller method and the app re-renders under the new locale with direction still RTL, derived from the locale — no hardcoded `Directionality` in this task's files.
- [ ] A language switch re-renders chrome only: no file in this task imports or renders any muṣḥaf/QPC/glyph surface.
- [ ] The theme picker offers exactly light / sepia / dark as named appearances; selecting re-tones via the appearance's `ColorScheme`; no raw hex/px/ms literal exists in this task's files (token names only — lint-verified).
- [ ] The Quran font-size/zoom control is a discrete named-step radiogroup persisting one ordered step; **no `Slider` exists in any of the three picker trees**; no muṣḥaf glyph or page preview renders anywhere in this task.
- [ ] Each selection routes through the single write path: exactly one transactional repository write per tap, committed before republish; the View never writes a preference.
- [ ] Every user-facing string is an `l10n.*` ARB key present in fa/ckb/ar (ar template; ckb flagged pending native + scholarly review); step magnitudes render in locale numerals, mixed runs FSI/PDI-isolated; no hardcoded user-facing text.
- [ ] Every option row is ≥48dp `touch.min`, a radiogroup member with a `Semantics` label + selected value and a visible focus ring; OS text scale never shrinks a row below 48dp; selected state is shape+text, never color alone.
- [ ] Switching is quiet and factual — no confetti/chime/badge/haptic fanfare, no "recommended"/"optimal", no preference framed as making revision "lighter"/"safe"/"done"; the adab conscience pass is recorded; no unregistered factual claim ships in any subtitle.

## Tests

All deterministic and offline by construction — seeded preference state, a recording settings repository, the injected clock where any date appears (none should), real bundled UI fonts. Consolidated per-locale RTL goldens live in E16-T12; this task ships the behavioural pins plus per-locale render smoke tests.

- `features/test/settings/language_picker_test.dart` (widget) — selecting a locale routes through the controller: the recording repository logs **exactly one** transactional write, and republish is observed only after commit; after the switch the tree re-renders under the new locale (a probe string resolves via the new `AppLocalizations`) with `Directionality.of` still RTL; the ckb row resolves `Locale.fromSubtags(languageCode: 'ckb')`; no English literal renders in any locale; no `Slider` in the tree.
- `features/test/settings/theme_picker_test.dart` (widget) — selecting an appearance logs exactly one write and re-tones the surface (the resolved `ColorScheme` changes to the named appearance's scheme); selected state is radio glyph + label (found by text, not by color); no `Slider` in the tree; a source-level check over this task's files finds no inline hex/px/ms literal.
- `features/test/settings/quran_zoom_picker_test.dart` (widget) — the steps render as a named radiogroup; selecting persists the chosen step (one write, value asserted on the recording repository); **no muṣḥaf glyph, QPC font, or page widget exists in the tree**; **no `Slider`**; step labels show locale-shaped numerals under fa/ckb/ar.
- `features/test/settings/display_pickers_locale_render_test.dart` (widget) — pumps all three pickers under each of fa/ckb/ar: every row ≥48dp with a `Semantics` label + selected value in a mutually-exclusive group, geometry RTL by `Directionality` derived from the locale, no missing-key fallback text.
- Offline guard: the suite runs under an `HttpOverrides` that fails any socket open (eng-write-dart-test) — a preference change is proven to make no network call.
- No-schedule-touch pin: across all three tests the recording repository shows **zero** writes to any engine/`EngineConfig`/card/`review_log` surface — only the named preference field changes.
