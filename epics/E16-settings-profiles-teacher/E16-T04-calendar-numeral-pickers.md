## Goal

Two Settings pickers land on the E16-T02 radiogroup primitive: the **calendar system** (Solar-Hijri/Jalālī · Hijri Umm al-Qurā · Gregorian) and the **numeral system** (Extended Arabic-Indic ۰۱۲ for fa/ckb · Arabic-Indic ٠١٢ for ar). Each persists exactly one presentation enum through the single write path, and each is a **pure display transform over the stored data**: flipping either re-renders every user-facing date and number — Today's next-due, Progress history, the picker's own option labels — through E09's `CalendarPresenter` / `numberFormatFor(locale)` primitives, and mutates **no** stored instant, **no** `card.due_at`, and **no** engine state. This is the epic's highest-risk task (a "harmless" picker that silently rewrites the schedule is the invisible corruption the trust clamp exists to prevent), so it is **test-first**: the headline test — switch the calendar, then the numeral set, over a seeded profile and assert the stored instant and every `due_at` are byte-identical, only rendered strings changing — is written before any widget. The Hijri option carries the labelled **Umm al-Qurā civil-courtesy caveat** (a civil approximation; an observance's start may differ by sighting) and issues no observance ruling. Defaults are plain per-locale constants (Jalālī for fa, Umm al-Qurā lead for ar, the locale's numeral block), never inferred silently from `Locale.current`.

## Implementation notes

This task is presentation/wiring only: two option sets, one persisted preference each, and the re-render wiring. It computes no date, reorders no page, calls no engine function, opens no socket. The display-transform invariant is the whole point — so the headline test is written **first**, red, before either picker exists.

1. **Write the display-transform test first** (`eng-write-dart-test`). Seed a profile with cards carrying known `due_at` `epochDay` integers and `review_log` rows carrying known UTC-µs `reviewed_at` instants. Drive the calendar preference Jalālī → Hijri → Gregorian, then the numeral preference, through the controller. Assert after every flip: every stored `due_at` and every stored instant is **byte-identical** (compare the raw stored integers, not re-parsed dates); a recording engine/repository double saw **zero** engine calls and zero card writes; only the rendered strings differ. This is the epic's named risk-1 mitigation — it must exist before the widgets.
2. **Files** (in the `features` umbrella package, `lib/src/settings/`, per the T01 scaffold): `widgets/calendar_system_picker.dart` and `widgets/numeral_system_picker.dart` — each a thin instantiation of T02's `SettingsSinglePicker<T>` over an enum (`CalendarSystem` from E09; a `NumeralSystem`/digit-block enum for the numeral preference), plus the two option-set builders. No new radiogroup anatomy, no new state model — T02 owns that.
3. **Persist one enum, nothing else.** Selecting an option routes through one notifier method (`eng-create-riverpod-store` discipline, inherited from T02) that persists the preference transactionally **before** republishing. The persisted value is the enum name only — never a converted date, never a recomputed `due_at`, never a wall-clock string (PRD §10.3). Re-render happens because Today/Progress watch the preference provider and re-ask E09's presenter; nothing downstream is written.
4. **Options render through E09 — never view-built.** Each calendar option row labels itself with its name **and** a preview of the injected today's date rendered by `CalendarPresenter` in that candidate system; each numeral option shows a sample run (e.g. ۱۲۳ vs ١٢٣) produced by `numberFormatFor` with the pinned `-u-nu-` tag. No widget in this task imports `shamsi_date`/`hijri` or builds a `Jalali`/`HijriCalendar` (engineering 07 §4) — verifiable by grep.
5. **The Hijri option carries the civil-courtesy caveat.** The option is labelled with the variant — "Hijri (Umm al-Qurā)", never "the Hijri date" in the absolute — and a one-line localized honesty note sits beneath it: a civil approximation; an observance's start may differ by a day by sighting (engineering 07 §6). The caveat states a fact and issues **no** observance ruling, names no sect's sighting authority, and never keys any app behavior to a Hijri date being exact. Register its exact fa/ckb/ar wording as a [TRAD] row via `domain-claims-register-and-science-screen` (nearest anchor **C-046**); as religious copy it does not ship without scholarly review.
6. **Verify digits per surface — the `intl` caveat is real.** Because `intl` historically shapes digits inconsistently between date and plain-number formatting (design-system 12 §4), assert the digit block on **both** a rendered date and a plain number, per locale: fa/ckb output contains U+06F0-range codepoints and no U+0660/ASCII digits; ar contains U+0660-range and no U+06F0/ASCII. Never string-replace digits to "fix" a wrong block — the fix is the pinned tag in E09's helper.
7. **Bidi-isolate every embedded run.** Date previews and digit samples inside RTL option labels go through the one isolation helper (engineering 12 §4) — `isolateLtr` for known-direction digit runs — as formatted ARB placeholders, never spliced substrings. A golden pins that a "day-month-year" preview never reorders.
8. **Strings via the ARB pipeline** (`eng-add-localized-string`): option names, the caveat, and any preview scaffolding are `l10n.*` keys in `app_ar.arb` (base) + transcreated fa/ckb; no hardcoded user-facing text.
9. **Inherited T02 duties still asserted per instance:** RTL by `EdgeInsetsDirectional`; ≥48dp `touch.min` rows; `Semantics` radiogroup with selected/not-selected values; selected = shape+text, never color alone; no `Slider`, no free text; switching is quiet — no confetti, chime, praise, or "recommended" marker on any option.
10. **Pitfalls to avoid:** recomputing or "refreshing" a `due_at` on switch (the invariant this task exists to pin); constructing a calendar object in a widget; letting a calendar package's Latin digits reach a widget (remap is downstream, in E09); inferring the calendar from `Locale.current` instead of the explicit stored preference; storing a converted/wall-clock date; hardcoding a Gregorian grid or a Monday week-start anywhere a preview draws; applying UI numerals to the muṣḥaf page (chrome only); phrasing the caveat as a ruling ("Ramaḍān begins…") or as fear; `DateTime.now()` anywhere — previews use the injected `CalendarDate`.

## Acceptance criteria

- [ ] `settings/widgets/calendar_system_picker.dart` and `numeral_system_picker.dart` exist as instantiations of T02's primitive; grep over this task's files finds no `Jalali`/`HijriCalendar` construction, no `shamsi_date`/`hijri` import, no `DateTime.now()`, no `Slider`.
- [ ] Switching the calendar (any of Jalālī / Hijri Umm al-Qurā / Gregorian) or the numeral system persists exactly one enum through the single write path (persist-before-republish) and re-renders Today next-due, Progress history, and the option previews through E09's `CalendarPresenter` / `numberFormatFor` — with every stored instant and every `card.due_at` byte-identical and zero engine calls.
- [ ] Calendar option previews render the **injected** today in each candidate system; numeral option samples render through `numberFormatFor` with the pinned `-u-nu-` tags; fa/ckb show U+06F0-range digits and ar shows U+0660-range digits on both dates and plain numbers — no ASCII digit reaches any option or re-rendered surface.
- [ ] The Hijri option is labelled "Umm al-Qurā" (never "the Hijri date" absolutely) and carries the one-line civil-courtesy caveat in fa/ckb/ar; the caveat issues no observance ruling and its wording is registered ([TRAD], anchored to C-046) via the claims register.
- [ ] Defaults are per-locale constants — Jalālī for fa, Umm al-Qurā lead for ar, the locale's numeral block — set as an explicit stored preference, never silently inferred or switched from `Locale.current`.
- [ ] Every embedded date/number run in the pickers is a formatted, FSI/PDI-isolated placeholder; a rendered date preview never reorders ("30 of 7" never occurs) visually or in screen-reader order.
- [ ] Every user-facing string is an `l10n.*` ARB key in fa/ckb/ar; layout is RTL by geometry; each option is a ≥48dp radiogroup row with `Semantics` selected value and a visible focus ring (inherited from T02, asserted here per instance).
- [ ] The switch is quiet and factual — no celebration, no "recommended", no urgency, no copy framing any calendar or numeral choice as more correct or more pious.

## Tests

All deterministic and offline by construction: injected `CalendarDate` (never a real clock), seeded fixtures, real bundled fonts, no socket. The display-transform test is written **first**.

- `features/test/settings/calendar_numeral_display_transform_test.dart` (widget/unit) — **written first, the headline invariant**: seed a profile (cards with known `due_at` epochDays; `review_log` rows with known UTC-µs instants); flip calendar Jalālī → Hijri → Gregorian, then the numeral set; after every flip assert the raw stored integers are byte-identical, a recording engine double saw zero calls, no card/`review_log` write occurred, and the rendered next-due/history strings **did** change (proving the transform is display-side, not a no-op).
- `features/test/settings/calendar_numeral_picker_test.dart` (widget) — selection routes through the controller's persist-before-republish method (a recording repository asserts persist precedes republish); options are a radiogroup with selected = shape+text; no `Slider` in the tree; previews come from a spy `CalendarPresenter`/`numberFormatFor` (proving the E09 path, not a view-built string); defaults resolve per locale (fa → Jalālī, ar → Umm al-Qurā lead).
- `features/test/settings/numeral_digit_block_test.dart` (unit/widget) — per locale, asserts the option samples **and** a re-rendered date **and** a plain number all carry the correct block (fa/ckb: U+06F0–U+06F9 present, U+0660-range and ASCII digits absent; ar: the converse) — pinning the `intl` date-vs-number inconsistency per surface.
- `features/test/settings/hijri_caveat_test.dart` (widget/unit) — the caveat renders adjacent to the Hijri option in fa/ckb/ar; the label contains "Umm al-Qurā"; asserts no ruling/observance-assertion phrasing (no "Ramaḍān begins", no sighting verdict, no guilt/fear) and that the ARB key is present in all three locales and registered in `docs/science/CLAIMS.md`.
- `features/test/settings/calendar_numeral_golden_test.dart` (golden) — per-locale (fa/ckb/ar) RTL goldens of both pickers on the real bundled fonts: correct digit blocks, no date-run reorder, caveat placement, selected-state shape; consumed by E16-T12's consolidated suite.
- Offline guard: the suite runs under an `HttpOverrides` that fails any socket open — a preference change or re-render never touches the network (`eng-write-dart-test`).
