## Goal

The quick **active-profile switcher**: a quiet active-profile chip that shows *whose* data is on screen and opens a short list of the device-local profiles (self / students / child); selecting one flips the E16-T08 `activeProfileProvider` through the single write path, and — because every scoped provider is `family`-keyed by `ProfileId` — the **whole app re-scopes**: today's session, the `review_log`, the retention heat-map, and the cards all now show the selected profile's record, with **no stale cross-profile leak**. This is the operable half of privacy-as-trust (§17, R5): the switcher is a device-local affordance, never a server dashboard, and a switch opens **no socket** (C-048). It is test-first: the headline tests — *switch re-scopes the read models* and *switch opens no socket* — are written before the widget is polished. Switching is a quiet re-scope: no confetti, chime, streak, or haptic fanfare, and no per-profile score, rank, or "completion %" ever renders (C-044 as guard). Create/rename is E16-T08, delete is E16-T11, and the halaqa hand-off into E12's sign-off is E16-T10 — this task owns only the switcher widget and the re-scoping behavior.

## Implementation notes

This task is presentation + wiring only: it draws the chip and the list, and calls the T08 controller. It computes no date, builds no query, opens no socket, and adds no write path. The two headline invariants — re-scope and no-socket — are pinned **test-first**, before any visual polish.

1. **Files** (in the `features` umbrella package, `lib/src/profiles/`, per the eng-add-feature-module anatomy T08 established):
   - `widgets/active_profile_chip.dart` — a dumb chip showing the active profile's bidi-isolated display name with a localized `Semantics` label ("Active profile: {name}; switch profile"); tapping opens the switcher list. Flat Level 0–1, thumb band, ≥48dp.
   - `widgets/profile_switcher.dart` — the short list (bottom sheet or compact menu) of all profiles from `ProfilesNotifier`, each row = bidi-isolated name only (+ the quiet parent-managed marker for a child, text not iconography-alone); the active row is *selected* per 07-components §6 (filled emphasis + check glyph + `Semantics` selected flag). Tapping a row awaits the T08 controller's switch method, then closes.
   - No new provider and no new repository method: the widget watches `profilesProvider`/`activeProfileProvider` (T08) and calls the existing switch mutation. If T08's controller lacks a needed read shape, extend T08 — do not fork a second profile store here.
2. **The re-scope is the provider graph's job — do not re-implement it.** Selecting a profile sets one value on the T08 controller (persist-before-republish); every `family(ProfileId)` provider (today queue, heat-map, cycle config, cards) recomputes and every Drift `StreamProvider` re-emits (eng 04 §1.2, §3, §5). The switcher must NOT manually refresh, invalidate, or rebuild any downstream provider, and must not pass data between profiles — if a manual `ref.invalidate` seems needed, a scoped provider is un-keyed and that is the bug to fix (in T08/the consumer, not here).
3. **No stale leak is an asserted invariant, not a hope.** The headline widget test seeds two profiles (A with pages due, B with a different set) on in-memory Drift + a `FixedClock`, renders a scoped read model, switches A→B, and asserts B's rows appear **and A's rows are gone** — pumping past the async gap so a one-frame leak of A's data also fails.
4. **The switch opens no socket — prove it.** The suite installs the throwing `HttpOverrides` (eng-define-service-boundary; eng-write-dart-test) so any connection attempt during list-open, switch, and re-scope is a loud failure. The switcher imports no networking symbol (the analyzer ban already covers this — keep it true).
5. **Names are user-typed free text — isolate them.** Every rendered name (chip, row, `Semantics` string) is an FSI/PDI-isolated placeholder via the E09 helper inside the localized message (12-localization §3): "Active profile: {name}" with `{name}` isolated, never `'label' + name` concatenation. One `Text` run per name; a long name ellipsizes within the row, it never wraps the RTL chrome.
6. **Selected ≠ color alone.** The active row carries filled emphasis + a check glyph + the `Semantics` selected state; `color.accent.green` may tint the selection but shape + text carry it (07-components §6; a11y "never color alone").
7. **Quiet, calm, nameless-of-rank.** No confetti, chime, streak bump, or haptic fanfare on switch — a restrained state change with at most `motion.duration.short`/`motion.curve.standard`, degraded to instant under reduce-motion. **No per-profile stat of any kind** in the chip or list: no percentage, rank, page count, "last reviewed", or "completion %" (C-044 guard; skill Pattern 9). A row is a name.
8. **No clock, no engine, no PII.** The widget never reads `DateTime.now()` (the re-scoped day is computed downstream from the injected `CalendarDate` — skill Pattern 7); it calls no engine API; it renders only `Profile.displayName` + the parent-managed flag — there is no other field to show (§17).
9. **Accessibility:** chip and every row ≥48dp `touch.min`; the list is a labelled group whose rows announce name + selected/not-selected + button role; visible focus ring (`color.outline`); the post-switch announcement is one calm `Semantics` update ("Active profile: {name}"), not a celebratory alert. States mirror correctly under RTL.
10. **Pitfalls to avoid:** an un-keyed provider read that survives the switch (stale leak); manual invalidation papering over a missing `family` key; mutating `activeProfileProvider` from the widget instead of the controller method; a per-profile score/percent/"last seen" on a row; a delete/rename affordance (T11/T08); any sign-off/verdict affordance (T10/E12); `'…' + name` string splicing; `EdgeInsets.only(left:)`; a chime/confetti/haptic fanfare; `DateTime.now()` anywhere in `lib/src/profiles/widgets/`.

## Acceptance criteria

- [ ] `profiles/widgets/active_profile_chip.dart` and `profile_switcher.dart` exist in the `features` package; both are dumb widgets that watch T08 providers and call the T08 switch method — no new provider, no repository method, no engine call, no `DateTime.now()`, no networking import (verifiable by grep over the files).
- [ ] Tapping a profile row flips `activeProfileProvider` through the T08 single write path (persist **before** republish) and every scoped read model — today's session, `review_log`-derived views, heat-map, cards — re-keys to the selected profile with no manual invalidation in the widget.
- [ ] After a switch, **none** of the previous profile's data renders on any scoped surface, not even for one frame gap the tests can observe; two profiles' data never appear together.
- [ ] A switch (open list → select → re-scope) opens **no socket**, proven by the throwing-`HttpOverrides` suite; the switcher performs no network transfer of any profile data (C-048).
- [ ] The chip and every row render the user-typed display name as a single, FSI/PDI-isolated run inside localized messages; mixed Latin/Arabic names do not break the RTL row in fa/ckb/ar.
- [ ] The active row is selected by shape + text (filled emphasis + check glyph) with the `Semantics` selected flag — never color alone; rows and chip are ≥48dp with M3 state layers and a visible `color.outline` focus ring.
- [ ] No per-profile percentage, rank, score, page count, or "completion %" exists anywhere in the chip or list (C-044); the switch is quiet — no confetti, chime, streak, or haptic fanfare; motion degrades under reduce-motion.
- [ ] Every string (chip label, list title, `Semantics` templates, parent-managed marker) is an `l10n.*` ARB key in fa/ckb/ar (ckb flagged pending native review); no hardcoded user-facing text.

## Tests

All deterministic and offline by construction: in-memory Drift, seeded profiles, a `FixedClock` `CalendarDate` (never a wall clock), the throwing `HttpOverrides` installed suite-wide. The first two are **written first**.

- `features/test/profiles/profile_switcher_rescope_test.dart` (widget, **written first**) — seeds profiles A and B with disjoint card/log fixtures; renders a scoped consumer (the `family`-keyed today/heat-map read models); switches A→B via the switcher; pins: B's data renders, **A's data is absent** (queried by A's distinctive fixtures), the switch routed through the T08 controller with persist-before-republish (a recording repository double asserts commit ordering), and no widget-level `ref.invalidate` was needed.
- `features/test/profiles/profile_switcher_offline_guard_test.dart` (widget, **written first**) — under the throwing `HttpOverrides`, opens the list, switches profile, and pumps the full re-scope; any connection attempt fails the test by name (C-048 made executable; eng-write-dart-test §8 posture).
- `features/test/profiles/profile_switcher_widget_test.dart` (widget) — chip + rows ≥48dp; `Semantics`: chip announces "Active profile: {name}; switch profile", rows announce name + selected/not-selected + button role; visible focus ring on keyboard traversal; selected = check glyph + emphasis, asserted present without relying on color; **no** text matching a percent/score/rank/count pattern renders on any row (C-044 guard); no delete/rename/sign-off affordance in the tree.
- `features/test/profiles/profile_switcher_bidi_test.dart` (widget) — user-typed mixed-direction names (Latin-in-RTL and Arabic-with-Latin-token) render as isolated runs in fa/ckb/ar: asserts the FSI/PDI isolates wrap the name placeholder and row order/ellipsis stays correct in RTL.
- `features/test/profiles/profile_switcher_quiet_test.dart` (widget) — a switch fires no haptic fanfare (a fake haptic boundary records none), no chime, no confetti/celebration widget; the transition uses at most `motion.duration.short` and degrades to instant under reduce-motion.
- `features/test/profiles/profile_switcher_golden_test.dart` (golden) — per-locale (fa/ckb/ar) RTL goldens of the chip and the open switcher (active row selected, a child profile row with its marker, one mixed-script name), on the real bundled fonts; feeds E16-T12's consolidated suite.
