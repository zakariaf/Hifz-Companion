## Goal

Scaffold the pure-Dart `backup/` package under the pub workspace and author its **public value-type surface only**: the `BackupSnapshot` top-level value object (`schemaVersion` int, `appVersion` string, `exportedAt` floating `"YYYY-MM-DD"` string, `List<ProfileExport> profiles`, plus the `mushaf {id, riwayah, name, checksumSha256}` reference the §4 payload carries), the `ProfileExport` value type mirroring the PRD §10.2 per-profile user model, the `BackupMode` enum (`plaintextJson` / `encryptedJson`), the distinct typed `BackupError` enum (`notAHifzBackup`, `newerFormat`, `unknownMode`, `integrityFailed`, `wrongPasswordOrDamaged`, `malformedPayload` — never a generic catch-all), and the `abstract final class HifzBackup` façade with the exact documented signatures `export(BackupSnapshot, {String? passphrase}) → Uint8List` and `import(Uint8List, {String? passphrase}) → BackupSnapshot`, bodies stubbed to `UnimplementedError` until T02–T05 fill the pipeline. The load-bearing deliverable is the **dependency WALL**: the pubspec depends on the shared value-type `models` package + Dart-team `crypto` and nothing else — never `drift`, `sqlite3`, `http`/`dio`, or `dart:io` networking — so "export/import sends nothing" and "the package cannot read the database" are provable by reading one manifest. No container bytes, no JSON codec, no hashing, no crypto, no UI, no string a user ever sees.

## Implementation notes

This task is API-surface-only: value types, enums, and two stubbed static methods. It is the foundation T02–T05 build on, so the shape must match `docs/engineering/10-backup-format.md` §1 to the letter — every deviation here becomes a format bug later. CLAIMS: none — this task introduces no user-facing number, string, or claim.

1. **Files** (per eng-create-package): `packages/backup/pubspec.yaml`; barrel `lib/backup.dart` exporting the stable surface only; `lib/src/backup_snapshot.dart` (snapshot + `ProfileExport` + the muṣḥaf reference value), `lib/src/backup_mode.dart`, `lib/src/backup_error.dart`, `lib/src/hifz_backup.dart` (the façade). Add `packages/backup` to the root `workspace:` list; `resolution: workspace`; `environment: sdk: ^3.6.0`; **no** Flutter environment line (the absence is audit evidence). SPDX/REUSE header on every Dart file. No `utils/`/`helpers/`/`common/` folder.
2. **The dependency wall is the deliverable.** `dependencies:` = the E03 `models` package + `crypto`, exactly — `crypto` is declared now because §5/T04's SHA-256 is this package's charter (the At-a-glance Module row and 10 §5 sanction it; the eng-create-package §3.1 matrix predates the `backup/` module, so record the new edge in the PR + E01 dep-allow-list as the skill's "decision-log-level event" note requires — never silently diverge). `cryptography` (Argon2id/ChaCha20) is **not** added here; T05 adds it. `dev_dependencies:` = `test` only; the suite runs under plain `dart test`.
3. **Copy the §1 Specification block verbatim.** `enum BackupMode { plaintextJson, encryptedJson }`; `enum BackupError` with exactly the six members **in the documented order** and their per-member doc comments (`notAHifzBackup` — magic mismatch … `malformedPayload` — JSON decode / schema validation failed); `abstract final class HifzBackup` with `static Uint8List export(BackupSnapshot snapshot, {String? passphrase})` and `static BackupSnapshot import(Uint8List fileBytes, {String? passphrase})`. Bodies: `throw UnimplementedError('E17-T02..T05 fill the export/import pipeline');` — a loud stub, never a silent empty return. (`import` as a method name is a built-in identifier, legal Dart — keep the documented name.)
4. **`BackupSnapshot` carries the §4 muṣḥaf reference.** The §1 Dart sketch lists `schemaVersion`/`appVersion`/`exportedAt`/`profiles`; the normative §4 payload table *also* carries top-level `mushaf {id, riwayah, name, checksumSha256}` — so the value model adds an immutable muṣḥaf-reference value type (id, riwāyah, name, checksumSha256 — strings only, **no glyphs/text/fonts/layout**). This is a documented reconciliation of §1's sketch with §4's table, noted in the code's `///` doc — not an invented field.
5. **`ProfileExport` mirrors §4 / PRD §10.2, composing the E03 `models` value types** (the same immutable records the DAOs map to — never Drift row classes, never parallel hand-rolled DTOs): `profileId` (stable UUID string), `profile`, `cycleConfig`, `cards`, `lineBlocks`, `reviewLog`, `confusionEdges`. It carries **no derived/health state** (no juz/ḥizb %, no forecast, no Today list, no notification cache) and **no Quran glyph/text/font/layout field** — the two §4 refusals, structural from day one.
6. **Immutability + standards** (eng-write-to-coding-standards): every field `final`; `const` constructors where possible; list fields defensively wrapped `List.unmodifiable`; value `==`/`hashCode`; `copyWith` on the snapshot types; `///` on every public symbol (each doc names its governing section, e.g. "10 §4"); full-word names; `dart format` + analyzer clean, zero suppressions.
7. **The barrel is the API contract.** `lib/backup.dart` exports exactly: `BackupSnapshot`, `ProfileExport`, the muṣḥaf-reference value, `BackupMode`, `BackupError`, `HifzBackup` — nothing else, ever, from `lib/src/`. T02–T05 add internals under `lib/src/`, not exports; other packages may never import `backup/lib/src/` (eng-create-package Pattern 3).
8. **Dates stay strings at this layer.** `exportedAt` is the floating `"YYYY-MM-DD"` text form — no `DateTime` field for any scheduling day anywhere in the model (`CalendarDate` semantics are E02's; T03 owns encoding, including UTC ISO-8601 for true instants). Do not "helpfully" parse or reformat dates here; the model transports text verbatim.
9. **Store-blind, I/O-blind, effect-free.** No import of `dart:io` at all in `lib/` (not even for `File` — the package does bytes in, bytes out via `Uint8List` from `dart:typed_data`); no clock, no randomness, no `print`/logging of user data (a passphrase or a display name in a log line would be a privacy break — eng-write-to-coding-standards Pattern 7).
10. **Typed errors are the restore UX.** T02's normative parse order returns one distinct `BackupError` per stage and T08 maps each to calm localized copy — so this enum's names and meanings are load-bearing API. Document on each member which parse stage emits it (per the §1 comments and the §3 order) so a later contributor cannot repurpose one as a catch-all.
11. **Pitfalls to avoid:** importing `drift` "just for a row type" (use the `models` values); adding `meta`/`cryptography` speculatively (audit-minimal — an unused edge is a review reject); putting header offsets, sorted-key JSON, hashing, or KDF logic here (T02–T05 own those stages); adding a `schemaVersion` default or auto-stamp (the shell stamps it from Drift at snapshot-build time, E17-T07); a seventh `BackupError` member or a generic `unknown`; making the façade instantiable or non-`final`; exporting anything from `lib/src/` outside the barrel; a mutable `List` field that lets a caller edit a snapshot after construction.

## Tests

All pure-Dart `package:test`, run by plain `dart test` in `packages/backup/` — deterministic and offline by construction (there is nothing here that *could* open a socket, which is the point).

- `packages/backup/test/dependency_boundary_test.dart` — **written first**, the wall made executable:
  - parses `pubspec.yaml` and asserts the dependency set is exactly `{models, crypto}` (dev: `{test}`) — an added edge fails the test before it fails CI;
  - walks every `.dart` file under `lib/` and asserts no import of `dart:io`, `package:drift`, `package:sqlite3`, `package:http`, `package:dio`, or `package:flutter` (the package-local twin of the E01 banned-import gate, so the wall breaks loudly at `dart test` time too).
- `packages/backup/test/backup_snapshot_test.dart` — value-type behavior: two structurally equal snapshots are `==` with equal `hashCode`; `copyWith` derives without mutating the original; the `profiles`/`cards`/`reviewLog` lists reject mutation (`UnsupportedError`); `exportedAt` is carried verbatim as a string (no parsing, no reformatting); the muṣḥaf reference holds the four documented string fields.
- `packages/backup/test/backup_error_and_mode_test.dart` — pins the enum contract T02–T05 build on: `BackupError.values` is exactly the six documented members in the documented order (a rename/reorder/addition breaks the pinned list); `BackupMode.values` is exactly `[plaintextJson, encryptedJson]`.
- `packages/backup/test/no_quran_fields_test.dart` — the epic's R1 risk mitigation at the model layer: walks the `lib/` sources and asserts no declaration names a glyph/text/font/layout/mutashābihāt-carrying field; the muṣḥaf reference exposes only the four documented strings (the byte-level "Quran never in the file" assertion over real payloads lands in T03/T04).
- `packages/backup/test/hifz_backup_facade_test.dart` — the façade exposes the two documented signatures (compile-time-checked by calling them through typed tear-off assignments `Uint8List Function(BackupSnapshot, {String? passphrase})` / `BackupSnapshot Function(Uint8List, {String? passphrase})`); both stubs throw `UnimplementedError` — never return a value — so no caller can ship against an unimplemented pipeline.
- Gate check (not a test file): `dart analyze` clean, `dart format --set-exit-if-changed` clean, `reuse lint` passes on the new files; the E01 banned-import/no-network and dep-allow-list gates run green over the new package (the gates are E01's — this task only lives under them and records the `crypto` edge on the allow-list).
- No `TZ`-matrix run is needed here — nothing in this task parses or computes a date; the ≥2-`TZ` format-harness obligation lands with T04.
