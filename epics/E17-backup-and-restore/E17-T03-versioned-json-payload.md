## Goal

The body of a `.hifzbackup` file, implemented as a pure-Dart (de)serializer over the E17-T01 `BackupSnapshot` value model: a **complete, value-typed, canonical (sorted-key, byte-deterministic) UTF-8 JSON export of the per-profile user data and NOTHING else** (engineering 10 §4). Top-level keys are exactly `schemaVersion` (int, stamped from the Drift `schemaVersion` carried in the snapshot), `appVersion` (informational only, never logic), `exportedAt` (floating `"YYYY-MM-DD"`), `mushaf {id, riwayah, name, checksumSha256}` (identity only — no glyphs, no text), and `profiles[]`. Each `ProfileExport` serializes `profileId`, `profile`, `cycleConfig`, `cards`, `lineBlocks`, the append-only `reviewLog`, and `confusionEdges`, keyed by stable UUIDs carried verbatim. Scheduling days (`dueAt`, `lastReviewAt`, `lastConfusedAt`) encode as floating `"YYYY-MM-DD"` (the `CalendarDate` serial-day text form); true event instants (`reviewedAt`, `createdAt`) as UTC ISO-8601. Decode validates and migrates older `schemaVersion` payloads forward through explicit per-version functions on the value types; `schemaVersion > current` ⇒ `newerFormat`; unknown keys within a known version are ignored; missing required fields / invalid enums ⇒ `malformedPayload`. This task owns **only the JSON body codec and its versioning** — not the binary container (E17-T02), not the SHA-256 hashing (E17-T04), not the encryption envelope (E17-T05) — and it never reads the DB: the snapshot arrives pre-built from the shell (E17-T06/T07 through `/data`).

## Implementation notes

This task is pure serialization: no I/O, no Drift, no crypto, no clock, no user-facing string. The codec is a deterministic function between `BackupSnapshot` and canonical UTF-8 bytes, and its determinism, truth-only schema, and version gates are pinned test-first before the façade is wired.

1. **Files** (in the E17-T01 `backup/` package, per eng-create-package boundaries already in force): `lib/src/canonical_json.dart` (deep key-sort + `dart:convert` UTF-8 encode), `lib/src/payload_codec.dart` (`encodePayload(BackupSnapshot) → Uint8List`, `decodePayload(Uint8List) → BackupSnapshot`), `lib/src/payload_migrations.dart` (the per-version forward functions). Imports: the value model + `dart:convert`/`dart:typed_data` only — no `crypto` (T04's), no `dart:io`, no Drift.
2. **Canonical encoding is a deep, recursive key sort** over the JSON map *before* `jsonEncode`/`utf8` — sorting only the top level is the classic miss. Deterministic bytes are the contract T04's hash and goldens stand on (doc 10 §4: "we refuse non-deterministic JSON"). Never rely on map insertion/iteration order; lists keep the snapshot's order (the `reviewLog` is an ordered audit trail — do not sort rows).
3. **Top-level shape exactly per doc 10 §4** — the five keys and nothing else. `schemaVersion` is stamped from the snapshot's Drift-carried value, never a codec constant (the file and the DB speak one version language, doc 10 §3); `appVersion` is written but **never read for logic**; `exportedAt` is a floating date the shell computed from the injected `CalendarDate` — the codec formats what it is handed, it never reads a clock.
4. **`ProfileExport` fields exactly per the doc 10 §4 tables** (reproduced in the Context row above). `errorLinesJson` and `settingsJson` are carried as the opaque strings the store holds — do not parse, normalize, or re-encode their inner JSON (re-encoding would break byte-stability and mutate an audit-trail row).
5. **Two date encodings, never confused**: scheduling days (`dueAt`, `lastReviewAt`, `lastConfusedAt`) are floating `"YYYY-MM-DD"` — the `CalendarDate` serial-day's zero-padded text form, formatted from `(y, m, d)` integers; true event instants (`reviewedAt`, `createdAt`) are UTC ISO-8601. **Pitfall:** never route a scheduling day through `DateTime`/`toIso8601String()`/locale formatting — a `DateTime` instant shifts a day across a DST/timezone boundary, the exact off-by-one E02 forecloses. The file is locale-independent: ASCII digits, fixed forms, no locale numerals ever.
6. **Identity is carried verbatim.** `logId` and `profileId` are stable UUIDs assigned at row creation; encode and decode pass them through untouched — they are the content addresses that make T06's merge a deduplicating set union. Never regenerate, normalize, or lowercase an id on decode.
7. **Truth only — enforce it structurally, then assert it.** The `BackupSnapshot` model has no derived field (no juz/ḥizb health %, no Today list, no forecast, no notification cache), so the codec *cannot* emit one; a schema-key golden additionally asserts no such key — and **no Quran key** (no glyph/text/font/layout/mutashābihāt field) — ever appears (PRD §10.3, R1). The `mushaf` object is identity-and-checksum only.
8. **Decode is gate-first, total, and typed.** Read `schemaVersion` before touching anything else: `> current` ⇒ `newerFormat` (before any migration work, and — by construction of the pure package — before any DB write). Then validate + migrate: missing required field or invalid enum value ⇒ `malformedPayload`; unknown keys within a known `schemaVersion` are ignored (additive-optional fields, noted in the public format changelog). No raw `FormatException`/`TypeError`/cast error escapes the codec — every failure maps to the E17-T01 `BackupError`.
9. **Forward migration mirrors Drift's discipline** (doc 05 §4): explicit, append-only, per-version functions on the decoded *value types* (`migratePayloadV1ToV2(…)`-style), chained stepwise up to current — never a SQL replay, never an edit to a shipped migration. The documented anchor: `confusionEdges.lastConfusedAt` is a floating serial day *since the schema-v2 migration* (doc 10 §4), so the v1 fixture pins that older form mapping forward; each future bump adds one function + one fixture.
10. **The format is public documentation — keep it honest.** The payload shape ships as the documented "never trapped" artifact (PRD §16; doc 10 is written so a third party can reimplement it). Any additive-optional field must be noted in the public format changelog; any change to an existing field's meaning requires a `schemaVersion` bump (doc 10 §4) — the codec must not quietly deviate from the doc 10 §4 tables, and if a field cannot be implemented as documented, stop and surface it rather than drift.
11. **Pitfalls to avoid:** a shallow key sort; re-encoding `errorLinesJson`/`settingsJson`; a scheduling day via `DateTime`; stamping `schemaVersion` from a constant; migrating before gating `newerFormat`; deduping or reordering `reviewLog` rows in the codec (merge semantics are T06's, and only over `logId`); leaking `schemaVersion` into T02's cleartext header; computing a digest here (T04's); importing `crypto`, `dart:io`, or anything Drift-shaped into these files.

## Acceptance criteria

- [ ] `encodePayload` produces canonical UTF-8 JSON: keys sorted at **every** depth, byte-identical across repeated encodes and across differently-constructed-but-equal snapshots; `decodePayload(encodePayload(s)) == s`.
- [ ] The top-level object carries exactly `schemaVersion`, `appVersion`, `exportedAt`, `mushaf {id, riwayah, name, checksumSha256}`, `profiles[]`; each `ProfileExport` carries exactly the doc 10 §4 fields for `profile`, `cycleConfig`, `cards`, `lineBlocks`, `reviewLog`, `confusionEdges`.
- [ ] `dueAt`, `lastReviewAt`, and `lastConfusedAt` encode as floating `"YYYY-MM-DD"`; `reviewedAt` and `createdAt` encode as UTC ISO-8601; encoded bytes are identical under different `TZ` environments; `logId`/`profileId` round-trip verbatim.
- [ ] No derived field (health %, forecast, Today list, notification cache) and no Quran field (glyph, text, font, layout, mutashābihāt) exists in the model or the emitted JSON — pinned by the schema-key golden.
- [ ] Decode gates `schemaVersion > current` ⇒ `BackupError.newerFormat` before any migration or value construction; older payloads migrate forward through explicit per-version functions to the current shape; the v1 `lastConfusedAt` fixture lands as a floating serial day.
- [ ] Within a known `schemaVersion`, an unknown key is ignored; a missing required field or invalid enum ⇒ `BackupError.malformedPayload`; no untyped exception escapes the codec on any malformed input.
- [ ] The codec files import only the value model + `dart:convert`/`dart:typed_data` — no `crypto`, no `dart:io`, no Drift, no networking (verifiable by grep; the E01 banned-import gate stays green).
- [ ] `reviewLog` rows pass through unmodified: no dedup, no reorder, no mutation, `errorLinesJson`/`settingsJson` byte-preserved as opaque strings.
- [ ] `appVersion` is written but never read for logic (decode has no branch on it); `exportedAt` and every date are formatted from values the snapshot carries — no `DateTime.now()` or clock read anywhere in the codec (verifiable by grep).
- [ ] The emitted shape matches the doc 10 §4 tables field-for-field; any additive-optional field this task introduces (none expected) is noted in the public format changelog, and no existing field's meaning changed without a `schemaVersion` bump.

## Tests

All pure `package:test` in `backup/test/`, deterministic and offline by construction (the package cannot open a socket); property tests use a seeded generator with the seed logged on failure and the suite runs under ≥2 `TZ` values in CI — both doc 10 §10 conventions. The fully-assembled container+hash harness is E17-T04 — these pin the codec alone.

- `backup/test/payload_roundtrip_test.dart` (property) — `decodePayload(encodePayload(s)) == s` over seeded arbitrary multi-profile snapshots including teacher sign-offs (`source: teacher` + `teacherLabel`), line blocks, and confusion edges; UUIDs, `reviewLog` order, and opaque JSON strings verbatim.
- `backup/test/payload_canonical_test.dart` (unit + golden) — repeated encodes are byte-identical; two equal snapshots built with different map insertion orders encode to the same bytes; a committed v-current fixture is byte-stable (the golden T04's digest asserts over); keys verified sorted at nested depths.
- `backup/test/payload_schema_keys_test.dart` (golden) — walks every key at every depth of a maximal encoded snapshot and asserts **no** glyph/text/font/layout/mutashābihāt key and **no** derived key (health/forecast/today/notification) is present; the top level is exactly the five documented keys; `mushaf` is exactly `{id, riwayah, name, checksumSha256}`.
- `backup/test/payload_dates_test.dart` (unit, ≥2 `TZ`) — `dueAt`/`lastReviewAt`/`lastConfusedAt` match `^\d{4}-\d{2}-\d{2}$` (zero-padded, ASCII digits); `reviewedAt`/`createdAt` are UTC ISO-8601 (`Z`-suffixed); the same snapshot encodes to identical bytes under `TZ=Asia/Tehran` and `TZ=Pacific/Kiritimati`, including across a DST-change date.
- `backup/test/payload_migration_test.dart` (fixture) — one committed fixture per historical `schemaVersion` decodes and migrates forward to the current shape with expected records (v1 pins the pre-v2 `lastConfusedAt` form landing as a floating serial day); `schemaVersion: current + 1` ⇒ `newerFormat` with zero migration/value-construction side effects (nothing for the shell to write — the T06 DB-untouched guarantee starts here); missing required field, invalid enum, and non-object payloads each ⇒ `malformedPayload`, never an untyped throw; an unknown key within the current version decodes cleanly and is dropped.
- Offline by construction: the suite is pure `dart test` with no `dart:io`/socket import to guard against — the E01 banned-import gate over `backup/` is the structural proof; no test reads a clock or an environment beyond the CI-set `TZ`. (The assembled container + integrity + timezone-invariance harness over the T02+T03 plaintext path lives in E17-T04.)

- [ ] All acceptance criteria met; the canonical/round-trip/schema-key/date/migration tests were written first and are green under ≥2 `TZ` values in CI.
- [ ] **Offline / no-network**: the codec adds no import beyond the value model + `dart:convert`/`dart:typed_data`; the `backup/` package still cannot open a socket and the E01 banned-import/no-network gate stays green (C1, PRD §17).
- [ ] **No AI / no microphone**: the payload is a deterministic serialization of stored truth — nothing records, infers, or scores (C2, R5).
- [ ] **Quran text fidelity (R1)**: no Quran byte can enter the file — the schema has no field for glyphs/text/fonts/layout/mutashābihāt and the schema-key golden proves the emitted JSON never grows one; the muṣḥaf is referenced by `{id, riwayah, name, checksumSha256}` only.
- [ ] **Never "safe to drop" / nothing decays silently**: only truth (D/S/`dueAt`, the log, configs) is exported — no derived health ships as an authority a stale import could resurrect; the receiving engine recomputes and re-clamps (E17-T06/E04), so nothing in this file can tell a ḥāfiẓ a page is safe to stop revising (PRD §10.3, §7.12).
- [ ] **The append-only `review_log` is honored**: rows are carried verbatim — never mutated, deduped, reordered, or dropped by the codec; `logId` survives byte-exact as the *sanad*-preserving merge key (PRD §10.3; doc 05 §2).
- [ ] **No gamification / no shame (R3)**: the schema contains no streak, score, badge, or "days missed" field — there is nothing here to gamify or to shame with; the codec introduces no user-facing copy.
- [ ] **RTL + fa/ckb/ar**: no user-facing string ships in this task (error surfacing copy is T02/T08's); the file format itself is locale-independent — ASCII digits, fixed date forms, no locale numeral or localized date ever encoded.
- [ ] **Accessibility**: no UI surface in this task; the a11y obligations ride the consuming surfaces (E17-T08/T09).
- [ ] **Boundaries respected**: no container/header bytes (T02), no SHA-256 (T04), no envelope (T05), no DB read/write (T06/T07 via `/data`), no `CalendarDate` math or calendar display (E02) — this task encodes text forms only.
- [ ] **Coding standards**: full-word identifiers, `///` docs on `encodePayload`/`decodePayload`/each migration function, total decode with every failure mapped to the typed `BackupError`, `dart format` + analyzer clean.
- [ ] **Deterministic tests**: seeded property generators (seed logged), committed byte-stable goldens, no clock read anywhere in codec or tests; all gates stay green.
