## Goal

Two deliverables, both confined to the pure-Dart `backup/` package. **(1) The mandatory SHA-256 body-integrity check as a feature**: on export, `HifzBackup.export` stamps `sha256(body)` (32 bytes, Dart-team `crypto`) into the container header at offsets `[16 … 48)`; on import, the reader recomputes the digest over the body bytes `[48 …]` at parse step 6 — after the cheap structural checks, **before any JSON decode, migration, or return of a snapshot** — and refuses the file on any mismatch with `BackupError.integrityFailed`, fail-closed. The check is stated plainly, in API docs and downstream copy, as **corruption detection, not tamper resistance** — a plaintext file's hash sits in the same file an attacker could rewrite (engineering 10 §5). **(2) The assembled plaintext-mode format harness** that pins T02's container and T03's payload together end-to-end: committed golden `.hifzbackup` v1 plaintext fixtures that decode to byte-exact known snapshots with every §3 header offset asserted; the `import(export(s)) == s` round-trip property; single-flipped-byte rejection (avalanche); the full truncation-boundary matrix with the *right* distinct error per stage; and timezone-shift invariance — the whole suite run under **at least two `TZ` values in CI**. This task stops at encryption's door: mode `0x02`, wrong-passphrase, Argon2 param-clamp, and the ciphertext-envelope hash nuance are **E17-T05**; everything shell-side (merge/replace, trust-clamp-after-import, cross-muṣḥaf, crash-mid-import, erase) is **E17-T06/T07**. It reuses — never re-implements — T02's parser and T03's codec.

## Implementation notes

This task is format-and-tests only: no Drift, no `dart:io` beyond reading committed fixture files in tests, no widget, no user-facing string (the calm copy behind `integrityFailed` is E17-T08's). The harness is written **test-first** against the T02+T03 plaintext path.

1. **Files.** In `backup/`: complete the integrity stage of the façade (e.g. `lib/src/integrity.dart` per the T01 skeleton) — `bodyDigest(Uint8List body)` → 32 bytes via `sha256.convert(body).bytes`, and `verifyBody(body, storedDigest)` with the §5 length+content compare. Committed fixtures live under `backup/test/fixtures/*.hifzbackup`; a small `tool/`-style generator script (run locally, output reviewed in the diff) produces them from a fixed literal `BackupSnapshot` — two profiles, teacher sign-offs in the `reviewLog`, `lineBlocks`, `confusionEdges`, known UUIDs, fixed floating dates and UTC instants, RTL/combining-mark display names.
2. **Export wiring.** The header bytes `[16 … 48)` are the digest of the *exact* body bytes written at `[48 …]` — compute over T03's final canonical JSON bytes, never over a re-encoded copy (a second `jsonEncode` pass that re-orders keys would stamp a hash of bytes that were never written). Keep the digest helper mode-agnostic (bytes in, digest out) so T05 hashes its envelope with the same function.
3. **Import wiring — verify is step 6, exactly.** After length ≥ 49, magic + `0x1F`, format-version, mode, and length-field-matches-file checks (T02's stages 1–5), recompute and compare; mismatch ⇒ `integrityFailed` and **nothing further runs** — no JSON decode, no migration, no partial `BackupSnapshot` ever escapes the function. Prove the ordering with a fixture pair: an invalid-JSON body with a *correct* hash ⇒ `malformedPayload` (step 8 reached), the same body with a *wrong* hash ⇒ `integrityFailed` (step 6 short-circuits).
4. **Honesty in the API.** The `///` doc on the verify path states: this detects corruption (truncated transfer, bit rot, clipped sync); it is **not** tamper resistance, because a plaintext file's hash travels in the same file; authenticity comes only from the mode-`0x02` AEAD tag (10 §5). Never "verified secure" / "tamper-proof" in any identifier, comment, or downstream copy.
5. **Golden test.** Decode each committed fixture and assert deep value-equality against the known literal snapshot, **and** assert the raw bytes: every §3 offset/value from the table above, the stored digest equals a recompute over `[48 …]`, and total length = `48 + n`. Also commit one fixture per *historical* `schemaVersion` (starting at v1) and run it through the full `import` path to current — extending T03's unit-level migration coverage to whole-file level without duplicating its per-version function tests.
6. **Truncation matrix.** Cut the golden at every boundary — mid-magic, 6, 7, 8, mid-length-field, mid-reserved, mid-hash (any length in `[16, 48)`), exactly 48, and mid-body — and assert the **right** distinct error per §3 stage: everything below 49 bytes and any file whose length ≠ `48 + n` is `notAHifzBackup` (steps 1/5); only a *same-length* body corruption reaches step 6 and yields `integrityFailed`. Collapsing the matrix to "throws anything" is a review reject.
7. **Flip properties (seeded).** A seeded generator picks an arbitrary body byte index and flips one bit ⇒ `integrityFailed`, for arbitrary generated snapshots (the avalanche property makes any single change detectable). Separately: flipping a *header* byte yields the structural error of its stage (never a decoded snapshot, never `integrityFailed` for magic/version/mode/length bytes). Log the seed on failure (10 §10) so a red run is reproducible.
8. **Round-trip property.** `import(export(s)) == s` (value equality on the T01 models) over generated arbitrary histories: multi-profile, empty profile, empty and large `reviewLog`, teacher sign-offs, unicode/RTL display names — mirroring the §10 row.
9. **Timezone-shift invariance.** Two layers: (a) a property asserting `export(s)` produces byte-identical output on repeated runs and that all encoded dates match the floating-`"YYYY-MM-DD"` / UTC-ISO-8601 forms exactly (no `.toLocal()` anywhere — the package never touches a clock); (b) the real cross-`TZ` proof: the committed goldens were generated under one `TZ` and the **CI matrix re-runs the whole suite under two `TZ` values** (pick two on opposite sides of UTC, e.g. `Asia/Tehran` and `America/New_York`) — decode must be byte-exact under both. The matrix is a minimal edit to the existing E01-owned `backup/` test lane (two `TZ` env entries); if that lane does not exist yet, flag it to E01 rather than building new gate infrastructure here.
10. **Discrepancy to surface, not paper over:** [EPIC.md](EPIC.md) and the skill say "2 reserved zero bytes," but the normative §3 table has **3** reserved bytes at offsets 13–15 (only 6+1+1+1+4+**3** = the 16-byte header that makes min-file 49 arithmetically true). Assert against §3 and raise the wording slip as an epic/skill erratum — never silently pick.
11. **Standards.** Every test file carries the REUSE SPDX header, full-word unit-bearing identifiers (`bodyBytes`, `storedDigest` — never `b`, `h`), typed `catch`, no `print`, `dart format` clean (eng-write-dart-test pattern 11); the hand-laid truncation-boundary table may use a justified `// dart format off` region where alignment *is* the documentation.
12. **Pitfalls:** hashing header+body together (digest covers `[48 …]` only); `==` on `List<int>` digests; decoding before verifying; a fixed "lucky" generator seed; regenerating goldens in CI; importing `flutter_test`/Drift/`dart:io` networking into `backup/`; testing mode `0x02` here (T05); asserting shell behaviour here (T06/T07).

## Acceptance criteria

- [ ] `HifzBackup.export` stamps the 32-byte `sha256(body)` at header offsets `[16 … 48)`, computed over the exact body bytes written at `[48 …]`; the digest helper is mode-agnostic and uses only `package:crypto`.
- [ ] `HifzBackup.import` recomputes the digest at parse step 6 — after T02's structural stages, **before** any JSON decode or migration — and a mismatch surfaces `BackupError.integrityFailed` with no partial snapshot escaping (fail-closed), proven by the correct-hash/wrong-hash invalid-JSON fixture pair.
- [ ] No MD5/SHA-1 symbol exists anywhere in `backup/` (grep-verifiable); the verify path's `///` docs state the corruption-not-tamper distinction in those terms.
- [ ] Committed golden v1 plaintext fixtures decode to byte-exact known snapshots; every §3 header offset, the min-49-byte rule, `length == 48 + n`, and stored-digest-equals-recompute are asserted; a historical-`schemaVersion` fixture migrates forward through the full `import` path.
- [ ] One flipped body byte at any generated index ⇒ `integrityFailed`; a flipped header byte ⇒ its stage's structural error — both as seeded properties with the seed logged on failure.
- [ ] Every truncation boundary is rejected with the **right** distinct `BackupError` per the §3 stage that catches it — never a generic throw.
- [ ] `import(export(s)) == s` holds as a property over generated multi-profile histories, and `export` output is byte-identical across repeated runs.
- [ ] The whole `backup/` suite is pure `package:test` (no `flutter_test`, no widget binding, simulator-free) and runs green under **at least two `TZ` values** in CI, with the committed goldens decoding byte-exact under both.
- [ ] The reserved-bytes wording discrepancy (EPIC/skill say "2", the normative §3 table has **3** zero bytes at offsets 13–15) is raised as an explicit erratum on the epic/skill, and the goldens assert the §3 table — the conflict is surfaced, never silently picked.

## Tests

All pure-Dart `package:test` in `backup/test/`, run with `dart test`, offline by construction (the shared throwing-`HttpOverrides` bootstrap stays installed), generators seeded with the seed printed on failure; goldens regenerated only by the local reviewed generator script.

- `backup/test/integrity_test.dart` — **written first**: digest placement at `[16 … 48)` over the exact body bytes; verify-precedes-decode ordering (invalid-JSON body: correct hash ⇒ `malformedPayload`, wrong hash ⇒ `integrityFailed`); valid body + wrong hash ⇒ `integrityFailed`, never a snapshot; digest-compare checks length and content.
- `backup/test/integrity_flip_property_test.dart` — seeded property: one flipped bit at an arbitrary body index of an arbitrary exported snapshot ⇒ `integrityFailed`; flipped header bytes ⇒ the matching structural error per stage.
- `backup/test/round_trip_property_test.dart` — `import(export(s)) == s` over generated histories (multi-profile, empty/large logs, teacher sign-offs, RTL/combining-mark names); repeated `export(s)` calls are byte-identical (T03 sorted-key determinism observed end-to-end).
- `backup/test/golden_files_test.dart` — each committed fixture decodes byte-exact to its literal snapshot; every §3 offset asserted; min-file 49 rule; the historical-`schemaVersion` fixture imports forward to current records.
- `backup/test/truncation_test.dart` — the full boundary matrix (mid-magic → mid-body) asserting the per-stage error; the same-length-corruption vs shorter-file distinction (`integrityFailed` vs `notAHifzBackup`).
- `backup/test/timezone_invariance_test.dart` — encoded dates are exactly floating `"YYYY-MM-DD"` / UTC ISO-8601; export bytes carry no locale/zone artifact; paired with the CI `TZ` matrix (two values spanning UTC) under which the entire suite — goldens included — must pass unchanged.
- `backup/test/fixture_generator_test.dart` — running the fixture generator twice over the same literal snapshot yields byte-identical output, so a future reviewed regeneration can never smuggle in nondeterministic bytes.

## Definition of Done

- [ ] All acceptance criteria met; the harness was written test-first against the T02+T03 path and is green under both `TZ` pins; the fixture-generator script and committed golden bytes are reviewed in the diff; CI only verifies, never regenerates.
- [ ] **Offline / no-network**: `backup/` still imports no networking package and no Drift/`sqlite3`; tests read only committed fixture files; the throwing-`HttpOverrides` guard and the E01 banned-import gate stay green (C1, PRD §17).
- [ ] **No AI / no microphone**: the integrity check and every fixture are deterministic functions over stored truth — nothing records, infers, or scores (C2).
- [ ] **Quran text fidelity (R1)**: no golden fixture embeds Quran text, glyphs, fonts, or layout — fixtures carry only the `mushaf {id, riwayah, name, checksumSha256}` reference, and a test greps the fixture payloads to prove no sacred-text field exists (10 §4).
- [ ] **Nothing lost silently (PRD §7.12; the "never safe to drop" covenant's data-side twin)**: the fail-closed gate makes a truncated or corrupted file *loudly* refusable — a half-copied backup can never import as silently-partial review history, and no fixture or copy implies any page is droppable.
- [ ] **No gamification / no shame / honest register**: this task ships no user-facing string; `integrityFailed` stays a typed enum for E17-T08's calm copy, and nothing in names, docs, or comments oversells the hash as security or dresses corruption detection up as a safety guarantee (10 §5).
- [ ] **RTL + fa/ckb/ar**: no UI here, and the format itself is locale-independent — the fixtures' RTL/combining-mark display names round-trip byte-exact, proving no locale or numeral form leaks into encoded bytes (the localized surfaces are T08/T09's).
- [ ] **Accessibility**: no widget ships in this task; the a11y obligations attach to the T08/T09 surfaces — this task's contribution is the distinct per-stage `BackupError` that lets those surfaces announce a specific, plain-language failure.
- [ ] **Deterministic tests**: pure `package:test`, no wall clock anywhere (the package takes dates as data), seeded generators with the seed logged on failure, deep-sorted canonical bytes, byte-stable committed goldens, and the ≥2-`TZ` CI matrix — identical inputs, identical bytes, on every machine.
