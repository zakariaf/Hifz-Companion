## Goal

The foundation's absolute rule — *"if a statement is not registered here with at least one verified source and an evidence grade, the app must not state it"* (CLAIMS.md intro) — becomes a build that passes or fails, not a review hope. This task authors the release-blocking **grade-coverage / no-orphan-claim gate**: a deterministic, offline check asserting that (a) every claim id the app references or the science screen renders resolves to an E19-T01 register row, (b) every such row carries **≥1 source** and a grade that is a member of the **sealed `EvidenceGrade` set** (no grade is unknown), and (c) — as far as it can be machine-checked — no user-facing factual string elsewhere asserts a fact absent from the register. An orphan id, a sourceless row, or an unknown grade FAILS the build with the offender named; the gate is the CI enforcement of "renderer, never author" (11-the-in-app-science-screen.md §1: *the register, not the screen, is the gate*). This task authors ONLY the gate, its fixtures, and its CI wiring: it parses nothing new (it consumes T01's typed rows and loader), renders nothing (T04/T05/T07), and does not touch the existing E01 no-network / banned-import / dependency-allow-list plumbing — it adds one new gate and must give the existing gates nothing to catch. The gate never "fixes" data — it fails and points at the register.

## Implementation notes

This task is gate-plumbing only: no widget, no ARB value, no register edit, no engine call. The gate is a pure function over (T01's parsed rows) × (the repo's referenced-id and factual-string surface), wrapped in a thin script and one CI step. The four failure modes (orphan id, sourceless row, unknown grade, unannotated factual string) are pinned **test-first** against committed fixtures before the CI wiring lands.

1. **Files:**
   - `tool/verify_claims_coverage.dart` — a thin `main()` over a pure library function `verifyClaimsCoverage({required registerAssetPath, required scanRoots}) → ClaimsCoverageReport`, so tests call the function directly and CI runs the script.
   - `tool/test/claims_coverage_gate_test.dart` — the unit suite, **written first**.
   - `tool/test/fixtures/claims/` — `passing/`, `orphan_id/`, `unknown_grade/`, `sourceless_row/`, `unannotated_string/` fixture trees (each a tiny register + scan root).
   - One new step in the fast job of the CI workflow + the new row in the PRD-gate→job mapping table.
2. **One parser: T01's.** Import T01's loader and typed rows; never regex-parse the register a second time — a second parser is exactly the copy/data drift the one-directional chain forbids. The gate runs against the **actual bundled register data the app ships** (the same bytes T01 loads), not against `docs/science/CLAIMS.md` prose.
3. **Check (a) — id resolution.** Build the referenced-id set as the union of: every `C-NNN` token (documented regex, `C-\d{3}`) in app/feature source; every token in all fa/ckb/ar ARB files (values **and** `@`-metadata); and the science feature's rendered-id surface (T03's by-id read model keys off the same register, so it cannot invent an id by construction — the scan still catches hand-written references elsewhere: Today copy, onboarding, notifications, tooltips). Every referenced id must resolve to a T01 row; a dangling id fails, named with its file and location.
4. **Check (b) — row validity.** Every referenced row must carry ≥1 non-empty source entry and a grade that is a member of the sealed `EvidenceGrade` set. A sourceless row or an unknown grade fails, naming the row id and the offending column. Do **not** special-case C-048's `[TRAD-equivalent project rule]` grade here — how it maps into the sealed set is T01's parser contract; if it arrives unknown, the gate goes red and points at the register/parser.
5. **Check (c) — the orphan-fact heuristic, honestly scoped.** Establish the convention other tasks key to (T09 and every epic's string work): a user-facing ARB string that asserts a fact carries its claim id in the `@key` description metadata. The gate flags ARB values matching a small, maintained factual-pattern list committed under `tool/` (percentage signs incl. `٪`, day/week/month interval-claim shapes, research/evidence stems per locale) that carry **no** claim annotation. Document in the gate's header docs that this is the *machine-checkable subset* — the full guarantee remains the `domain-claims-register-and-science-screen` review; never claim the heuristic is complete.
6. **Failure is a defect named, never a silent skip.** Report **every** violation in one run (no fail-fast at the first hit), each naming the offending id / ARB key / row and which check failed; exit non-zero; output sorted so a red build is byte-stable. The gate never mutates the register, never inserts a placeholder grade or source, never downgrades to a warning.
7. **CI wiring per `eng-add-ci-check`.** Add to the fast job: `dart test tool/` (the gate's own suite) + `dart run tool/verify_claims_coverage.dart`, on every PR; the release job re-runs it with the full suite; `continue-on-error` is forbidden; inherit the pinned `flutter-version`. Add the gate→job mapping row citing 11 §1 + the E19 charter as its doc basis. If the team wants the claims gate enumerated inside PRD §20 itself, raise that as an explicit doc amendment — do not edit the PRD from this task.
8. **Deterministic and offline by construction.** Pure file IO over repo sources and the bundled register; no network, no model, no clock, no randomness, no environment-dependent ordering. The gate fetches nothing — "latest research" included (11 §2).
9. **Gate-script standards** (eng-add-ci-check pattern 10): REUSE SPDX header (`GPL-3.0-or-later`), full-word names (`referencedClaimIds`, not `ids`), a sealed violation type per check (never string-matching on messages), `dart format` clean, no `print` beyond the report (CI runs on source/assets only — there is no user data). No new dependency: `dart:io` file reads + T01's package + `package:test` only.
10. **Pitfalls to avoid:** a second ad-hoc register parser (drift between gate and screen); passing silently when the register asset or a scan root is missing (**missing input = fail-closed**, same discipline as the asset verifier); "fixing" data instead of failing; a heuristic so noisy the team marks the gate advisory (tune the pattern list — a gate that cries wolf dies by `continue-on-error`); testing only the green path; scanning only `app_ar.arb` (all three locales' ARBs carry facts); coupling the gate to widget code (it must run headless under `dart test`, no Flutter binding); publishing a "coverage percentage" (the gate is binary pass/fail).

## Acceptance criteria

- [ ] `tool/verify_claims_coverage.dart` exists as a thin shell over a pure `verifyClaimsCoverage(...)` library function; the gate consumes T01's loader and typed rows and contains **no second register parser** (verifiable by grep over `tool/`).
- [ ] Check (a): every `C-NNN` token referenced in app/feature source, all fa/ckb/ar ARB files (values + metadata), and the science feature's rendered-id surface resolves to a register row; a dangling id fails the build naming the id and where it was found.
- [ ] Check (b): every referenced row carries ≥1 source and a sealed `EvidenceGrade`; a sourceless row or an unknown grade fails naming the row — with no special-casing of any row (C-048's grade mapping lives in T01, not here).
- [ ] Check (c): an unannotated ARB value matching the committed factual-pattern list fails naming the key; the claim-id-in-`@key`-metadata convention and the "machine-checkable subset" honesty note are documented in the gate's header docs.
- [ ] A red run reports **all** violations with sorted, byte-stable output and a non-zero exit; the gate never mutates the register, never inserts placeholders, never warns-and-passes; a missing register asset or scan root fails closed.
- [ ] The gate runs on every PR in the fast job and in the release-job re-run; no `continue-on-error` anywhere; the PRD-gate→job mapping table names it with its doc basis (11 §1; E19 charter).
- [ ] The gate adds no new dependency and no networking import — the existing E01 no-network / banned-import / allow-list gates stay green with nothing new to catch.
- [ ] The gate script carries the REUSE SPDX header, uses sealed violation types and full-word names, and is `dart format` clean.
- [ ] Fixtures are committed and unmistakably synthetic where synthetic: the orphan id is `C-999` (no real row will ever collide — the register tops out well below it), the unknown-grade token is obviously fake (e.g. `[XX]`), and no fixture row invents a citation — real rows (C-035, C-046, C-047, C-048) are copied verbatim from the register, never paraphrased.
- [ ] The gate's own documentation (script header) states what it does NOT guarantee: the orphan-fact heuristic is the machine-checkable subset; semantic review of claim wording, grades, and sources remains the `domain-claims-register-and-science-screen` checklist and the scholarly-review pipeline.

## Tests

All pure `package:test`, headless, deterministic, **written first** against committed fixtures; the suite runs under the throwing-`HttpOverrides` bootstrap (the gate opens no socket — a stray fetch is a loud named failure, per eng-write-dart-test).

- `tool/test/claims_coverage_gate_test.dart` — **written first**:
  - **green path**: the `passing/` fixture register contains the real rows **C-047** ([OBS], name+date every source), **C-046** and **C-048** (sourced project-rule rows), and **C-035** (the `[TRAD]` row sourced by collection + number — *Ṣaḥīḥ al-Bukhārī* 5032 / *Ṣaḥīḥ Muslim* 791) with a scan root whose references all resolve and whose factual strings are annotated → the report is clean, exit 0; pins that a hadith-sourced `[TRAD]` row counts as sourced exactly like an empirical row;
  - **orphan id**: the `orphan_id/` scan root references a synthetic `C-999` with no row → FAILS, message names `C-999` and the referencing file/key;
  - **unknown grade**: the `unknown_grade/` fixture carries a row graded with a token outside the sealed set → FAILS naming the row id and the grade token (this also pins the C-048 class of edge: unknown-at-the-gate is red, never silently coerced);
  - **sourceless row**: the `sourceless_row/` fixture carries a referenced row with an empty source column → FAILS naming the id;
  - **unannotated factual string**: an ARB fixture value matching the pattern list with no claim annotation → FAILS naming the key; its annotated twin passes;
  - **fail-closed**: a missing register asset / missing scan root → non-zero with a named failure, never a green skip;
  - **determinism**: two runs over the same fixtures produce byte-identical reports (sorted output); multiple simultaneous violations are all reported in one run.
- **Library-first, one process smoke test**: every case above calls `verifyClaimsCoverage(...)` directly (no process-spawn flakiness, precise assertions on the sealed violation values); exactly **one** additional smoke test runs the script as a process against the passing and orphan fixtures and asserts exit code 0 / non-zero — pinning that the thin `main()` shell faithfully surfaces the report.
- **Real-data run**: once T01's bundled register lands, the gate runs against the actual shipped data in the same suite (not only fixtures) — proving the real register is fully sourced and graded today, and that C-048's grade maps into the sealed set via T01's contract rather than arriving unknown.
- **CI proof**: the workflow diff shows the `dart test tool/` + `dart run tool/verify_claims_coverage.dart` step in the fast job and the release-job re-run, with no `continue-on-error`; a deliberate local red run (the orphan fixture pointed at the real script) demonstrates the failure path end-to-end before merge — proving the gate runs on every PR and actually blocks.

## Definition of Done

- [ ] All acceptance criteria met; the fixture suite was written first and is green; the gate runs in CI on every PR and blocks the release when red — a gate, not a review hope.
- [ ] **Renderer-never-author, machine-enforced**: the one-directional chain (*verified source → graded claim → register row → copy → screen*) now has CI teeth — an orphan id, a sourceless row, or an unknown grade is a build failure naming the offender (11 §1; CLAIMS.md intro; domain-claims checklist).
- [ ] **Offline / no-network**: the gate opens no socket and fetches nothing ("latest research" included); it adds no networking import and no dependency, so the E01 no-network / banned-import / allow-list gates see nothing new; its suite runs under the throwing `HttpOverrides`.
- [ ] **No AI / no microphone (C1, C2, R5)**: the gate is static analysis over source and bundled data; no model generates, grades, or "fixes" anything — evidence grading stays human authorship in `CLAIMS.md`, out of scope for this whole epic.
- [ ] **Quran text fidelity (R1)**: the gate reads no Quran asset and interprets no sacred text — it touches only the claims register and UI-string surfaces; the muṣḥaf integrity gates are unaffected and stay green.
- [ ] **Never "safe to drop" / no promise**: the gate ships no copy; by refusing any ungraded or unsourced row it protects the no-promise chain — a grade describes the *evidence*, never certainty about the user's Quran, and nothing in the gate's output or docs frames a claim as "proven".
- [ ] **No gamification / no shame (R3, C6)**: the gate is binary pass/fail — no coverage percentage, badge, streak, or score is introduced as a target (a percentage gate is explicitly refused per eng-add-ci-check pattern 8); its failure messages address developers, never a user.
- [ ] **RTL + fa/ckb/ar**: the scan covers all three locales' ARB files (values + metadata) equally — an orphan fact in ckb fails the build the same as one in ar; the gate itself ships no user-facing string (its report is developer-facing CI output, exempt from the ARB pipeline).
- [ ] **Accessibility**: no UI ships in this task; its a11y contribution is upstream — every row T04/T05/T07 will render is guaranteed sourced and graded before it can reach a screen reader or a golden.
- [ ] **Deterministic tests**: no clock, no randomness, no network, sorted output, committed fixtures; the suite is green under `dart test tool/` on the pinned toolchain, and CI only ever verifies — nothing is auto-blessed or auto-fixed.
