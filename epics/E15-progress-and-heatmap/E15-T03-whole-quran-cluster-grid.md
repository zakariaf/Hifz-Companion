## Goal

The whole-Quran cluster grid exists as **pure geometry**: all 604 pages grouped into the 30 juz the ḥāfiẓ already holds in mind, laid out **in muṣḥaf order, start→end under the ambient RTL `TextDirection`** — juz ۱ at the logical start (visually right), juz ۳۰ at the logical end — built as **faithful small multiples**: one consistent juz block (size, `space.*` gutter, internal page order) learned once and read thirty times, assembling the E10 heat-map cell leaf (`ui-retention-heatmap` family) into each position. Interaction is *overview first → zoom → details-on-demand*: the overview tap unit is the juz block, a juz tap zooms to its pages, a page tap routes to the detail-sheet route (content owned by E15-T06) — the exact numbers live **behind a tap, never on the face of the grid**. This task **places** the leaf; it never **paints** it — the ramp colour, redundant number+label, and VSUP muting are E15-T04; the juz tile colour + weakest-page badge are E15-T05. The visualization layer is **glyph-free by construction**: no QPC font, no āyah, no ornament, ever (PRD R1).

## Implementation notes

This task is presentation-only geometry: no engine call, no `DateTime.now()`, no write path, no colour decision. It renders the T01 read model's page/juz structure through T02's providers and defers every encoding decision to T04/T05/T06.

1. **Files** (in the `features` umbrella package, `lib/src/progress/`, per the T02 scaffold): `widgets/quran_cluster_grid.dart` — the whole-Quran grid (the `RetentionHeatmap`-style `GridView`/sliver of 30 blocks from the `ui-retention-heatmap` template) plus the zoomed-juz view; `widgets/juz_block.dart` — the one small-multiple unit (block header + its pages' cell leaves in internal muṣḥaf order). Both are dumb stateless widgets taking the streamed read model + tap callbacks; wire into `progress_screen.dart`'s body without re-architecting T02's View.
2. **Muṣḥaf order is data, not arithmetic.** The page→juz grouping comes from the bundled fixed muṣḥaf dataset exposed through the quran/assets layer (the same fixed layout source E13 uses) — juz are **not** uniform ~20-page runs, so never derive the grouping as `page ~/ 20` or any constant; and **never reorder** blocks or cells by weakness, due date, or any metric — spatial order IS Quran order (08-data-visualization §7 anti-pattern; C-044).
3. **RTL by geometry, never a flipped flag.** The grid consumes the **ambient** `TextDirection` (RTL in all three locales per 12-localization §1) — do **not** wrap the grid in a hardcoded `Directionality(textDirection: TextDirection.rtl)`. Blocks flow start→end so juz ۱ sits at the logical start (visually right) and juz ۳۰ at the logical end, wrapping top-to-bottom; all insets/alignment via `EdgeInsetsDirectional`/`AlignmentDirectional` — no `left`/`right` anywhere (PRD §13.2).
4. **Small-multiple discipline.** One `JuzBlock` unit: consistent size, `space.2`/`space.3` gutters by token (never hairline gaps or raw dp), a block header naming the juz in locale numerals via `numberFormatFor(locale)` with the mixed run FSI/PDI-isolated ("جزء ۷"-style, per eng-rtl-and-bidi-layout), and internal pages in muṣḥaf order — thirty blocks, one act of learning (08-data-visualization §7).
5. **Assemble, don't paint.** Each page position instantiates the E10 heat-map cell leaf with the page's identity + tap callback only; the encoding inputs (band → `color.heatmap.*` token, localized value, plain label, VSUP muting) are threaded by **T04** — this task renders the leaf in its E10 default/neutral state and must not inline a colour, hex, number, or label onto the cell face.
6. **Overview-first touch targets.** In the overview the tap unit is the **juz block** (≥48dp `touch.min`, ≥`space.2` apart); tapping zooms to that juz's pages, where each page cell is itself a ≥48dp target. Do not make sub-48dp overview cells individually tappable, and put no exact number on the grid face — exactness is behind the tap (08-data-visualization §1; 05-layout §4).
7. **Tap-through routing.** A page tap opens the detail-sheet route (`go_router` route / modal-sheet scaffold) that **T06** populates — this task guarantees the correct page identity reaches the route and ships the empty scaffold only; a juz tap performs the zoom. No handoff to the reader here (that lives in T06 → E13); no mutation, no engine call on tap.
8. **Glyph-free by construction.** No QPC/muṣḥaf font family, no Quran text, no surah calligraphy, no ornament anywhere in these widgets — headers and semantics are UI chrome (`l10n.*` keys + locale numerals), never sacred text (domain-mushaf-text-integrity; PRD R1; 08-data-visualization §7).
9. **Accessibility & semantics.** Each juz block exposes one localized `Semantics` node (juz name/number + button role); zoomed page cells announce via the E10 leaf's semantics; traversal order follows the visual RTL order because the ambient `Directionality` drives both (09-accessibility §8); visible focus ring on tappable blocks/cells.
10. **Scroll & scale.** 604 leaves + 30 blocks must stay smooth: build the overview lazily (slivers / lazily-built `GridView`, never a `shrinkWrap`-everything `Column`), keep the juz block a fixed-extent unit so scrolling geometry is constant, scroll vertically only — the body never scrolls horizontally; the empty/loading treatment of the surface belongs to T09/T02, not here.
11. **Pitfalls to avoid:** a hardcoded `Directionality` or any physical `left`/`right`; assuming 20 pages per juz; reordering by weakness "to surface problems" (that is T07's list, not this grid); painting colour/number/label here (T04's job) or a juz tile colour (T05's); recomputing `R`/`due_at`/the aggregate in the widget; a glyph, āyah, or calligraphic decoration in the viz layer; hairline gaps that dissolve the small-multiple unit; swapping the faithful grid for a treemap/radial/packed-bubble chart; raw ASCII digits or an un-isolated "Juz N" run in a header.

## Acceptance criteria

- [ ] `progress/widgets/quran_cluster_grid.dart` and `progress/widgets/juz_block.dart` exist in the `features` package; both are dumb stateless widgets that take the streamed read model + callbacks and contain no engine call, no `DateTime.now()`, no write, and no `R`/`due_at`/aggregate recomputation (verifiable by grep over the files).
- [ ] The grid renders exactly **604** cell-leaf positions grouped into exactly **30** juz blocks, with the page→juz grouping read from the bundled fixed muṣḥaf dataset (no `~/ 20`-style arithmetic) and internal page order = muṣḥaf order; spatial order never changes with page weakness or any metric.
- [ ] Under the ambient RTL `TextDirection`, juz ۱ resolves to the **logical start** (visually right) and juz ۳۰ to the logical end; no `Directionality` widget is hardcoded in these files; all insets/alignment are `EdgeInsetsDirectional`/`AlignmentDirectional` — zero physical `left`/`right`.
- [ ] Juz blocks are consistent small multiples: same size, `space.*` gutters by token name (no raw dp, no hairline gaps), each headed by its juz number in locale numerals via `numberFormatFor(locale)`, FSI/PDI-isolated.
- [ ] Every interactive target (juz block in overview, page cell in the zoomed juz) is ≥48dp `touch.min` with ≥`space.2` separation; a juz tap zooms; a page tap opens the detail-sheet route carrying the correct page identity (content deferred to E15-T06).
- [ ] The grid face carries **no** exact number, percentage, label, or ramp colour painted by this task — cell encoding is deferred to E15-T04, juz tile colour + badge to E15-T05.
- [ ] No QPC/muṣḥaf font family, Quran text, or ornament appears anywhere in these widgets — the visualization layer is glyph-free (PRD R1).
- [ ] Each juz block exposes a localized `Semantics` label + button role; screen-reader traversal order matches the visual RTL order across fa/ckb/ar.
- [ ] The overview builds its blocks lazily (sliver/lazy `GridView`) and scrolls vertically only; the grid never overflows horizontally at any supported text scale.

## Tests

All deterministic, offline by construction, on real bundled UI fonts (never `Ahem`), with seeded read-model fixtures and no real clock (eng-write-dart-test).

- `features/test/progress/quran_cluster_grid_test.dart` (widget) — pumps a seeded 604-page read model: asserts exactly 604 cell-leaf positions in exactly 30 juz blocks; spot-checks juz-boundary pages against the bundled dataset (grouping is data, not arithmetic); under a mixed-weakness fixture the block and cell order is **identical** to a uniform fixture (spatial order never reorders by metric).
- `features/test/progress/cluster_grid_rtl_order_test.dart` (widget) — for each locale fa/ckb/ar under the app's ambient direction: a **reading-order assertion** (semantics traversal / logical hit-test order, not a pixel match) that juz ۱ resolves to the logical start and juz ۳۰ to the logical end; asserts no hardcoded `Directionality` and no `EdgeInsets.only(left:/right:)` in the task's files; block headers render locale numerals, bidi-isolated.
- `features/test/progress/cluster_grid_interaction_test.dart` (widget) — every tappable target measures ≥48dp with ≥8dp separation; a juz tap zooms to that juz's pages; a page tap pushes the detail-sheet route with the correct page identity (a fake `go_router`/navigator records the push); a recording repository/engine double asserts **zero** writes and zero engine calls on tap.
- `features/test/progress/cluster_grid_glyph_free_test.dart` (widget) — walks the rendered tree and asserts no text style resolves to a QPC/muṣḥaf font family and no Quran text/glyph codepoints appear — the viz layer is glyph-free by test, not by convention.
- `features/test/progress/cluster_grid_golden_test.dart` (golden) — per-locale (fa/ckb/ar) structural golden of the overview grid + one zoomed juz on real bundled fonts (cells in the E10 neutral state — encoding goldens live in T04/T05); these goldens feed the E15-T10 consolidated suite.
- Offline guard: the suite runs under an `HttpOverrides` that fails any socket open — the grid renders streamed state only and never touches the network.

## Definition of Done

- [ ] All acceptance criteria met; widget, RTL reading-order, interaction, glyph-free, and golden tests are green locally and in CI; the goldens are registered for E15-T10's consolidated suite.
- [ ] **Offline / no-network**: the grid renders streamed read-model state only — no fetch, no socket; the `HttpOverrides` guard passes (PRD C1).
- [ ] **No AI / no microphone**: nothing here records, transcribes, or infers; the grid is a read-only geometric surface (PRD C2).
- [ ] **Quran text fidelity (R1)**: the visualization layer renders no Quran glyph and tints none — no QPC font, no āyah, no ornament; the immutable glyph layer lives only in the reader (E13), pinned by the glyph-free test (domain-mushaf-text-integrity).
- [ ] **Never "safe to drop" (decay axiom)**: spatial order is muṣḥaf order — no page or juz is ever hidden, collapsed, dropped, or reordered out of view by strength or weakness; every one of the 604 positions renders every time (PRD §7.12; 08-data-visualization §7).
- [ ] **No gamification / no shame (R3, C6)**: the grid is a calm self-referential map (C-044) — no streak, score, rank, or leaderboard geometry, no celebratory treatment of a complete juz, no reordering that turns the muṣḥaf into a league table.
- [ ] **The View is dumb**: page identity, grouping, and health all arrive via the T01 read model through T02's providers; the widgets never read `DateTime.now()`, never call the engine, never write, and never recompute `R`/`due_at`/the roll-up.
- [ ] **RTL + fa/ckb/ar localization**: the grid flows start→end under the **ambient** RTL direction (no hardcoded `Directionality`); logical insets only; juz headers use locale numerals via `numberFormatFor(locale)`, FSI/PDI-isolated; any header string is an `l10n.*` ARB key in fa/ckb/ar — no hardcoded user-facing text, no raw ASCII digits.
- [ ] **Accessibility (WCAG 2.2 AA)**: every interactive target ≥48dp `touch.min` with ≥8dp separation (SC 2.5.8 cleared); juz blocks and cells expose localized `Semantics` with button roles and a visible focus ring; reading/focus order equals the visual RTL order (09-accessibility §8). Colour-independence of cell values is asserted in T04, where the encoding lives.
- [ ] **Sect-neutral adab**: the muṣḥaf's structure is honoured, not re-imagined — faithful juz→page order, no clever chart, no decoration of anything sacred; the page grouping comes from the bundled dataset of the active muṣḥaf (swappable, never assumed universal); the (minimal) header copy passed the adab conscience pass in all three locales.
- [ ] **Deterministic tests**: seeded fixtures, no hidden clock, no network; the reading-order assertion is structural (never a pixel match); goldens are byte-stable on the pinned bundled fonts; all CI gates stay green.
