## Goal

Beside the heat-map sits a **calm upcoming-load forecast**: how many pages are due over the coming days, so the user can plan — framed as a **planning aid** ("to help you plan"), NEVER a performance dashboard, a deadline pile, or a red overdue count (08-data-visualization §1; PRD §12.5). The surface renders per-day due-page counts derived from **E15-T01's streamed due-date data** — the widget never recomputes `R`, `due_at`, or the schedule, and never reads `DateTime.now()`; "today" and every due date arrive pre-computed from the read model's injected clock and the engine's trust clamp (PRD §7.6). Every count renders through an **ICU `plural`** message with Arabic's six CLDR categories, shaped to **locale numerals** via `numberFormatFor(locale)`; any day/date label renders through the one `CalendarPresenter` in the user's chosen calendar. It mounts into the E15-T02 host beside the map. A gap/backlog **routes to** the calm E12 catch-up plan — this task builds no banner and shows no "overdue" bucket (PRD §7.9).

## Implementation notes

This task is presentation-only: no engine call, no Drift query, no `DateTime.now()`, no mutation. It folds the E15-T01 streamed read model into per-day counts and renders them calmly. The copy and plural/numeral correctness are the risk → pinned test-first by widget tests + the banned-phrase lint before visual polish.

1. **Files** (in the `features` umbrella package, `lib/src/progress/`, inside the E15-T02 scaffold):
   - `widgets/upcoming_load_forecast.dart` — a dumb stateless `UpcomingLoadForecast` taking a pre-built `List<ForecastDay>` (a day + a due-page count); no state of its own, no engine, no clock, no navigation logic beyond an optional route-out.
   - The per-day grouping lives in the **ViewModel** (E15-T02's 1:1 `ProgressViewModel` or a small mapper beside it): a pure fold of T01's streamed per-page due dates into counts for the coming window (suggested: the next 7 days, one row per day). Grouping is presentation; it applies **no** interval math, floor, or clamp — those already happened in the engine (§7.6).
2. **"Today" comes from the read model, never the widget.** The window anchors on the injected-`Clock` "today" that T01 streams alongside the data. Grep-verifiable: no `DateTime.now()`, no `Clock` import, no engine import in this task's widget file.
3. **Planning-aid framing, structurally.** One quiet heading (e.g. ARB key `progressForecastTitle`, register "to help you plan"), then one calm row per day: day label + count. Copy in `type.body`/`type.caption`, `color.text.secondary` for the supporting text, flat surface — **no** `color.semantic.error`/red, no alarm icon, no KPI tiles, no totals banner, no trend arrows, no week-over-week comparison. A heavy day is information, not a warning; a zero-due day renders as a quiet localized "no pages due" row (the plural's `zero` form for ar), never a celebration and never "free day".
4. **No overdue bucket, ever.** Nothing due in the past renders as "overdue"/"missed"/"late N"; per §7.9 the engine has already re-spread any backlog, so the forecast simply shows the re-spread forward counts. If E15-T09's missed-day state is active, the forecast stays neutral — routing to the calm E12 catch-up plan is T09's/E12's job, not a red figure here.
5. **Counts through ICU `plural`, shaped first.** One count-bearing key (e.g. `progressForecastPagesDue`) as an ICU `plural` message with **all six** Arabic categories; the count is formatted via `numberFormatFor(locale)` **before** placement so digit shaping and number agreement are both correct (eng-add-localized-string; ui-numerals-calendar-text). No ternary, no splice, no ASCII digit anywhere in the rendered tree.
6. **Day labels through the one `CalendarPresenter`.** Relative labels ("today"/"tomorrow") are plain ARB keys; any actual date renders via `CalendarPresenter` in the user's chosen calendar (Jalālī / Hijri Umm al-Qurā / Gregorian) + locale numerals, remapped downstream of the conversion. The calendar choice re-renders labels only — it never changes which day a page is due (12-localization §5). If rows are ever grouped by week, week-start is CLDR locale data (Saturday for fa/ar), never a hardcoded Monday.
7. **If any copy explains *why* load clusters** (e.g. a supporting line noting the cycle guarantees each page a revision, so cycle days carry more pages), that line traces to **C-016** and says nothing beyond it. Add **no** un-registered claim; the counts themselves are descriptive and need no CLAIMS row. No retention percentage appears on this surface.
8. **RTL by geometry** (per the epic's RTL contract): `EdgeInsetsDirectional`/`AlignmentDirectional` only; day rows read start→end under `Directionality.rtl` with the day label at the logical start and the count at the logical end; every mixed run (count + label + date) is FSI/PDI-isolated; ckb's longer copy reflows within the same insets.
9. **Accessibility:** each day row exposes one `Semantics` label composing day + localized plural count in the active locale (spoken numerals natural, not English ASCII read-out); the surface never encodes load by colour alone — the number and label are the channels (any optional bar is redundant decoration); if a row taps through (e.g. to Today), targets are ≥48dp `touch.min` with a visible focus ring.
10. **Pitfalls to avoid:** recomputing `R`/`due_at`/the window in the widget (read T01's stream only); `DateTime.now()` anywhere; an "overdue"/"backlog"/"behind"/"deadline" word or bucket; red or alarm styling on a heavy day; a total/percent/score/trend framing (performance dashboard); a two-form plural for ar or an unshipped `zero`/`two`/`few`/`many` category; `"$count"` splice or ASCII digits; a hardcoded Gregorian/Monday grid; building the catch-up banner or the Today list here; celebrating or "safe-to-skip"-framing a light day; a mandate word in any string.

## Acceptance criteria

- [ ] `progress/widgets/upcoming_load_forecast.dart` exists in the `features` package as a dumb stateless widget taking pre-built per-day counts; grep over the task's files finds no engine import, no Drift symbol, no `DateTime.now()`, no `Clock` construction.
- [ ] The forecast renders one calm row per upcoming day (window anchored on the read model's streamed "today"), each showing a day label + a due-page count folded from E15-T01's streamed due dates — with no re-derivation of `R`, `due_at`, or any interval.
- [ ] No "overdue"/"missed"/"late"/"behind"/"backlog"/"deadline" word, bucket, or count exists in the ARB keys or the rendered tree; a zero-due day renders a quiet localized zero-form row, not a celebration; a heavy day renders with no red, no `color.semantic.error`, no alarm icon.
- [ ] Every count renders through an ICU `plural` message whose `ar` entry defines all six CLDR categories, with the count shaped via `numberFormatFor(locale)` before placement; no ASCII digit appears in any locale's rendered output.
- [ ] Any date label renders through the one `CalendarPresenter` in the chosen calendar + locale numerals; switching the calendar re-labels rows without changing any count or day boundary.
- [ ] Any copy explaining why load clusters traces to C-016 and no other factual claim is introduced; no retention percentage appears.
- [ ] Layout is RTL by geometry (`EdgeInsetsDirectional`/`AlignmentDirectional`, no `left`/`right`); mixed runs are FSI/PDI-isolated; ckb reflows without truncating a load-bearing label.
- [ ] Each day row exposes one `Semantics` label (day + localized count); load is never encoded by colour alone; any tap-through target is ≥48dp with a visible focus ring.
- [ ] The never-ship banned-phrase lint passes over all three locales for every string this task adds (no guilt/fear/loss, no mandate word, no deadline/overdue framing, no `!`/emoji); the adab conscience pass is recorded.

## Tests

All deterministic, offline by construction, real bundled fonts, seeded fixtures — the fake read model supplies "today" and the due dates; no hidden clock anywhere. Test-first on the copy/plural invariants.

- `features/test/progress/upcoming_load_forecast_test.dart` (widget) — **written first**: a fake E15-T01 read model seeds known due dates → the forecast renders the expected per-day counts; a past-due page in the fixture produces **no** overdue row (only the re-spread forward counts appear); a zero-due day renders the quiet zero-form row; the widget performs no engine/repository call (a recording double asserts zero reads beyond the stream) and renders no red/`color.semantic.error`.
- `features/test/progress/forecast_plural_numerals_test.dart` (widget/unit) — pumps counts 0, 1, 2, 3, 11, and 100 across fa/ckb/ar and asserts the correct ICU plural form is chosen (all six ar categories exercised) and every rendered digit is in the locale set (Extended Arabic-Indic fa/ckb, Arabic-Indic ar) — a regex over the tree fails on any ASCII digit, covering the `intl` date-vs-number caveat per surface.
- `features/test/progress/forecast_calendar_label_test.dart` (widget) — the same seeded window rendered under each of the three calendar choices yields identical counts and day boundaries with only the labels re-rendered via `CalendarPresenter`; no `Jalali`/`HijriCalendar` is constructed in the view.
- `features/test/progress/forecast_banned_phrase_test.dart` (unit) — runs the never-ship banned-phrase lint over every ARB value this task adds in fa/ckb/ar (overdue/missed/late/behind/deadline framing, guilt/fear/loss, mandate words, "safe to drop"/"done", `!`, emoji) and fails on any hit.
- `features/test/progress/upcoming_load_forecast_golden_test.dart` (golden) — per-locale (fa/ckb/ar) RTL goldens of a mixed window (a heavy day, a normal day, a zero day) on real bundled fonts; ckb-reflow golden proves no truncation; these goldens feed the E15-T10 consolidated suite.
- Offline guard: the suite runs under an `HttpOverrides` that fails any socket open — proves the forecast makes no network call.
