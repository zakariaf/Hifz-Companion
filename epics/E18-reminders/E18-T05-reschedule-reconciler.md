## Goal

The OS notification schedule is never a source of truth — it is a **rebuildable derived cache** of exactly one authoritative state: the committed reminder prefs (E18-T02). This task ships the one **reconcile routine** that makes that stance mechanical: on app start, on a preference change, and after a reboot or a permission grant, `cancelAll` unconditionally, then — only if the committed prefs say enabled — re-derive the single daily fire via E18-T04's pure fire-moment computation and place it with one `scheduleDaily` through E18-T01's injected boundary. The routine is **idempotent and convergent**: called once or N times, from any trigger, in any interleaving, it always lands the OS on exactly one scheduled fire matching the current committed prefs when enabled and exactly zero when disabled — never a duplicate, never a stale time surviving a restore, reboot, or OS notification-channel reset. Every pass performs a fresh committed read (it never trusts caller-supplied state), resolves `(now, today, location)` **once** from the injected clock/zone edge (no `DateTime.now()` anywhere), mutates nothing, and authors no copy. T03 owns the user-driven mutation path (persist-before-republish) and shares this routine as its post-commit scheduling call; T04 owns the fire-moment math; T08 owns the permission-request UX and only *calls* this on a grant; T09 later plugs content selection into this rebuild; T10 owns every string. **Test-first**: the idempotency/convergence suite over the T01 fake is written before the routine body.

## Implementation notes

This task is orchestration-only and correctness-critical: no widget, no schema, no OS API beyond T01's two verbs, no fire-moment math, no copy. The convergence guarantee is the epic's whole answer to restore/reboot/channel-reset divergence → the suite is written **first**, red on a stub.

1. **File & placement**: `app/lib/src/reminders/reminder_reschedule_reconciler.dart` — in the app shell beside T04's fire-time function, because a pass must name `tz.Location` to hand T04 its parameters and decision 14 quarantines the `timezone` types to this edge. The device zone arrives from the T01 live module's zone-resolution helper (the sole importer of `flutter_timezone`); this file imports the T01 interface, the T02 repository read surface, T04's function, and `timezone` types only — no `flutter_local_notifications`, no `flutter_timezone`, no Drift symbol, no Flutter widget.
2. **Shape**: one class, one public method — `Future<void> reconcile()` — with collaborators injected (the scheduler `Provider`, the prefs read surface, the clock/zone edge, the content seam); exposed as a `Provider<ReminderRescheduleReconciler>` bound in `composition/providers.dart` with zero logic in the provider body. `///` docs state the contract: cancel-then-rederive, idempotent, convergent, mutates nothing.
3. **The pass, in strict order**: (a) a fresh committed point read of the active profile's prefs (absent row = off); (b) `await cancelAll()` **unconditionally** — even when the read says off, so a stale fire from any past state (a restore, an OS channel reset, an older build) cannot survive; (c) only if `isEnabled`: resolve `(now, today = todayFor(now), location)` once, derive the instant via T04 from the committed time-of-day (T02's minutes-since-midnight split into T04's hour/minute inputs), and place exactly one `scheduleDaily` under the fixed id with the already-localized title/body from the injected seam. Off → the cancel-terminal state *is* the converged state. Never inspect the OS pending-notification list to decide anything — the OS state is untrusted by definition.
4. **Convergence over trust.** `reconcile()` takes no arguments carrying prefs or fire state; it re-reads truth every pass. A stale caller, a lost OS channel, an OS that kept or dropped anything across a reboot — all irrelevant: any trigger converges the OS to exactly what the committed prefs prescribe.
5. **Passes are serialized.** Overlapping triggers (a prefs change landing during the startup pass) chain on an in-flight future so one pass's cancel/derive/schedule never interleaves with another's (`cancelAll`₁ → `cancelAll`₂ → `schedule`₁ → `schedule`₂ is the drift shape to kill); the recorded verb stream is always whole passes, latest committed prefs win. The fixed notification id would make even an interleave converge (replace semantics, T01), but the guarantee here is structural, not incidental.
6. **Trigger — app start**: invoked exactly once from the app bootstrap after the composition-root overrides are installed (the app-start edge in `main`/root initialization) — never from a rebuilt widget `build`, never lazily on first Settings visit. This single trigger is also what heals a reboot and a `.hifzbackup` restore-then-relaunch.
7. **Trigger — preference change**: T03's post-commit side effect calls `reconcile()` (the one shared scheduling path; T09 follows the same precedent). The reconciler does **not** additionally subscribe to T02's watch stream — one trigger path per event, or a single change double-fires passes. A profile switch changes which committed row is authoritative and routes through the same routine as a preference-change trigger (keying follows T02's per-profile model — do not re-decide it here).
8. **Trigger — reboot & permission grant**: a reboot is not directly observable without extra OS surface this design refuses — it resolves to the **next app start**, which converges regardless of what the OS kept or lost; any plugin-level boot re-scheduling that exists is untrusted redundancy, and the start pass still runs `cancelAll`-then-rederive over it. A permission grant (in-context, or made in system settings and observed on resume) is detected by T08, which calls `reconcile()` — this task adds no permission code and no resume listener of its own.
9. **Failure is calm, typed, and convergent.** A failing pass (T01's sealed error) propagates as a value to its trigger: no crash at startup, no retry loop, no prefs mutation. The worst intermediate state — cancelled-but-not-rescheduled — is self-healing: the next trigger converges. Surfacing a truthful on/off row is T06/T08's concern; no copy exists here.
10. **Pitfalls to avoid:** scheduling before cancelling (the duplicate/stale window this task exists to close); skipping `cancelAll` when prefs read off (a stale fire survives a restore); diffing the OS pending list instead of wipe-and-rebuild; trusting caller-supplied prefs or an in-memory mirror instead of a fresh committed read; persisting anything, including "last scheduled at" bookkeeping (a second source of truth — the single write path stays T02/T03's, CLAUDE.md #10); subscribing to the prefs stream *and* being called by T03 (double passes); resolving `now` and `today` in two separate reads (the midnight straddle T04's contract forbids); `DateTime.now()`/`TZDateTime.now`/`tz.local` anywhere in the file (the eng-07 §5 grep covers `app/lib/src/reminders/`); deriving the fire moment inline (T04's); a retry loop, a second notification id, or an extra fire (an adab breach and a convergence break); authoring or hardcoding any string (T10's).

## Acceptance criteria

- [ ] `app/lib/src/reminders/reminder_reschedule_reconciler.dart` exists, exposing one public `reconcile()` routine behind a `Provider` bound in `composition/providers.dart`; the file imports the T01 interface, the T02 read surface, T04's function, and `timezone` types only — no `flutter_local_notifications`, no `flutter_timezone`, no Drift symbol, no `DateTime.now()`/`TZDateTime.now`/`tz.local` (grep-verifiable).
- [ ] Every pass performs, in order: fresh committed prefs read → **unconditional** `cancelAll` → (enabled only) exactly one `scheduleDaily` derived via T04 from one coherent `(now, today, location)` resolution; `cancelAll` strictly precedes any `scheduleDaily` in every recorded pass.
- [ ] Idempotent: N consecutive `reconcile()` calls with unchanged prefs leave exactly one scheduled fire (enabled) or zero (disabled) — never two — and every scheduled instant matches the committed prefs' time.
- [ ] Convergent across triggers: the sequence start → prefs change → restore (stale OS state seeded) → reboot-start → permission grant always terminates with the OS holding exactly what the then-current committed prefs prescribe — never a duplicate, never the stale time (proven by the seeded test, not by claim).
- [ ] Disabled prefs (or an absent row) converge to the cancel-terminal state: `cancelAll` runs, zero `scheduleDaily` calls follow, and no later trigger resurrects a fire while prefs stay off.
- [ ] The reconciler mutates nothing: zero repository writes, zero prefs changes, zero stored or in-memory mirror of the fire time, in every test scenario (a recording repository double proves it).
- [ ] Overlapping invocations serialize: the recorded verb stream contains only whole `cancelAll → [scheduleDaily]` passes, never an interleave; the latest committed prefs determine the final fire.
- [ ] Wiring: `reconcile()` runs exactly once at the app-start edge after composition-root overrides; T03's post-commit step and T08's grant path invoke the same routine; nothing triggers it from a widget `build`.
- [ ] A scripted scheduler failure surfaces as the sealed error value — no crash, no retry loop, no prefs mutation — and the next successful pass converges.
- [ ] The suite was written first (red on a stub); all added Dart passes `dart format --set-exit-if-changed` and `dart analyze --fatal-infos`, with `///` docs on the public API.

## Tests

All deterministic and offline by construction: T01's recording fake and a fake prefs repository installed via `overrideWith` (no mock framework), a **fixed injected clock** — literal `(now, today)` and an explicit `tz.Location` from the bundled tz database, never the host wall clock or `tz.local` — and the suite-wide throwing-`HttpOverrides` guard (eng-write-dart-test).

- `app/test/reminders/reminder_reschedule_reconciler_test.dart` (unit — **written first**): the single-pass contract — enabled prefs → the recorded verbs are exactly `cancelAll` then one `scheduleDaily` whose instant equals T04's derivation from the committed time-of-day and the fixed `(now, today, location)`; disabled or absent prefs → exactly `cancelAll`, zero schedules; N repeated calls → N identical whole passes and a terminal state of exactly one (or zero) fire under the fixed id; the fake repository records **zero writes**; mutating the fake's committed prefs between calls proves each pass re-reads truth (the next pass schedules the new time with no caller hint).
- `app/test/reminders/reminder_reschedule_convergence_test.dart` (unit) — the lifecycle gauntlet behind the epic's "Derived-cache convergence" DoD: start → prefs change → simulated restore (the fake pre-seeded with a stale fire at an old time, and separately with a duplicate) → reboot (the fake's recorded OS state wiped, then a start-trigger pass) → permission grant; after **every** trigger the fake holds exactly one fire matching the then-current committed prefs — never two, never the stale one; flipping to disabled mid-sequence converges to zero and stays zero across all remaining triggers.
- Serialization (in the reconciler test): two overlapping `reconcile()` invocations — the verb stream shows only whole passes, no interleaved cancel/schedule across passes, and the terminal state is one correct fire from the latest committed prefs.
- Failure path: the fake's scripted-failure switch fails one pass — the sealed error surfaces as a value, no prefs write occurs, the intermediate cancelled-but-unscheduled state is observable, and the following pass converges to the correct single fire.
- Offline guard: the throwing-`HttpOverrides` bootstrap is installed; nothing in this path opens a socket. (The fire-moment DST/timezone vectors are E18-T04's; persist-before-republish ordering is E18-T03's; permission flows are E18-T08's; catch-up content selection is E18-T09's.)
