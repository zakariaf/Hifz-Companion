## Goal

The optional "catch-up ready" note (PRD §14): a **second, independently off-by-default toggle** — a sibling to the daily reminder, never coupled to it — that, after a missed-day gap, surfaces **one** framed-as-help local notification mirroring the engine's **already-computed** re-spread plan: empathy first, then the honest fact and the concrete path ("a catch-up that still completes your cycle"), never blame, never "N days lost", never a red overdue pile. This task owns the toggle's *semantics* and the *content wiring* — T03's `ReminderController` already ships the persist-only `setCatchUpNoteEnabled` mutation onto E18-T02's `isCatchUpNoteEnabled` flag; this task makes that persisted flag mean something: a pure, total decision function that READS the E12 read model's backlog signal (the pre-built `TodayState.catchUp` / `CatchUpPlan` payload — days missed, plan length, as data) and selects what the single scheduled fire says. It computes **no schedule**: the re-spread math is the engine's (E04/E12), the fire moment is E18-T04's, the reconcile timing is E18-T05's, delivery is E18-T01's two verbs under the one fixed notification id. The on-screen Today catch-up **banner** is E12-T05 (`ui-catch-up-banner`) — this task builds no in-app surface. The note is fully silenceable in one tap, with no cadence escalation and no re-engagement mechanic; its fa/ckb/ar copy values are E18-T10's — this task defines the keys and their placeholders only.

## Implementation notes

This task is behavior + wiring only: no widget layout (T06), no copy values (T10), no schedule math (E04/E12), no fire-moment (T04), no OS call outside the injected boundary (T01). The adab invariants and the independence of the two toggles are correctness-critical → their tests are **written first**.

1. **Files** (beside the T03 controller in the reminders feature area): `catch_up_note_decision.dart` — a pure, total content-selection function; the reconciler input wiring that feeds the decision's output into T05's rebuild; the independence/adab suites below. The `setCatchUpNoteEnabled` mutation itself is T03's — this task adds no controller method, no new package, no new provider family beyond what T03/T05 already expose.
2. **The toggle is independent by construction — pin it, don't re-implement it.** T03's `setCatchUpNoteEnabled(bool)` already persists **only** `isCatchUpNoteEnabled` through T02's repository (one `db.transaction`, persist-before-republish, zero scheduler calls of its own); the committed change then lands in T05's on-change reconcile. This task pins the independence: the catch-up mutation never reads or writes `isEnabled` or the reminder time; flipping the daily toggle never touches the catch-up flag. Off is the schema default (T02 `DEFAULT 0`); enabling is one explicit tap on the T06 sibling switch; one tap silences it again — no confirmation dialog, no "are you sure", no exit friction (dark-pattern audit: no obstruction).
3. **The decision function is pure and computes no schedule.** `selectReminderNoteContent(ReminderPreferences prefs, CatchUpSignal? signal) → sealed NoteContent` with exactly three variants: `none`, `dailyReminder`, `catchUpNote(daysMissed, planLengthDays)`. `CatchUpSignal` is a plain-fields projection of the E12 read model's pre-built plan (days missed + plan length as integers) — the function does integer/boolean selection only: no engine import, no `loadBalance`, no clock, no I/O, no `DateTime`. Truth table: catch-up **off** → the daily body is never replaced (daily on → `dailyReminder`; daily off → `none`); catch-up **on** + signal present → `catchUpNote`; catch-up **on** + no signal → fall back to the daily decision. A backlog with the toggle off produces silence — never an auto-on, never a "we noticed you were away" surprise.
4. **Delivery rides the single existing slot.** At reconcile time (T05's triggers), the rebuild asks the decision function for content and passes the resulting **already-localized** title/body to the one `scheduleDaily` fire (T01's fixed id, T04's fire moment). At most one notification per civil day exists in any state; the note never adds a second id, a second fire, or a shortened cadence, and continued absence never escalates anything — the same single slot simply carries the help note while the signal persists and reverts/clears when it doesn't. When both toggles are off, the reconciler converges to `cancelAll` with no reschedule.
5. **The note's shape is empathy → fact → plan → choice** (voice §4; ui-catch-up-banner Pattern 1), glossed: calm acknowledgment, the honest fact ("You missed N days"), the concrete path ("here is an M-day catch-up that still completes your cycle"), and the choice left with the user (opening the app shows the E12 banner with the plan; the note demands nothing). The count appears **only** as the lead-in to help — never "N days lost", never standalone reproach, never a countdown or deadline.
6. **Keys, not values.** Define the ARB key contract this task needs — a title key and a count-bearing body key with `daysMissed`/`planLengthDays` placeholders (Arabic's six CLDR plural categories apply) — and wire the `l10n.*` lookups; T10 authors the transcreated fa/ckb/ar values and runs the voice gate. Counts render via the locale numeral path (`numberFormatFor(locale)`, Extended Arabic-Indic fa/ckb, Arabic-Indic ar) with mixed runs FSI/PDI-isolated; no string or digit is hardcoded in Dart.
7. **The signal is consumed, never derived.** "Is there a backlog / what is the plan" comes from the E12-owned read model (the `TodayState.catchUp` variant's `CatchUpPlan`, pre-built by the engine through E12-T02's controller path). This task maps it to `CatchUpSignal` at the seam and must not re-derive days-missed from dates (the elapsed-day math is E02/E12's, on the injected `CalendarDate` — no `DateTime.now()` anywhere in this task's files).
8. **Nothing here implies "safe to drop."** The note offers the plan; it never says the backlog is small enough to skip, never marks a page done/mastered, never suggests dropping manzil to shorten the plan (the engine keeps FAR mandatory per §7.9 — the note just mirrors whatever plan it produced).
9. **Pitfalls to avoid:** coupling the toggles (enabling catch-up flipping the daily on, or vice versa); auto-enabling after a gap "to be helpful"; computing the re-spread, days-missed, or any schedule in this task; a second notification id or an extra fire (a T05 convergence break and an adab breach); escalating cadence while a backlog persists; blame/loss copy ("you're behind", "N days lost", loss imagery, `!`); a red/urgent OS channel or custom alarm sound; building any on-screen banner or Today surface (E12's); authoring locale string values (T10's); calling the OS outside the injected T01 boundary; `DateTime.now()` in any file this task adds.

## Acceptance criteria

- [ ] The catch-up note toggle is **off by default** (T02 schema fact; an absent prefs row reads as off) and **independent**: T03's `setCatchUpNoteEnabled` persists only `isCatchUpNoteEnabled` in one transaction before republishing, and neither toggle's mutation reads or writes the other's field — pinned here in both directions (verifiable in the recorded write set).
- [ ] `selectReminderNoteContent` is a pure, total function over `(ReminderPreferences, CatchUpSignal?)` returning the sealed `none` / `dailyReminder` / `catchUpNote` — it imports no engine, Flutter, Drift, or clock symbol and contains no date arithmetic (grep-verifiable).
- [ ] The catch-up note content is selected **only** when the toggle is on AND the E12 backlog signal is present; toggle-off with a live backlog leaves the daily decision untouched; toggle-on with no backlog produces no note.
- [ ] Delivery uses only T01's existing verbs under the single fixed notification id via T05's reconcile — no new interface member, no second id, no additional fire, no cadence change; both-toggles-off converges to zero scheduled notifications.
- [ ] The note body follows empathy → fact → plan → choice; the days-missed count appears only as the lead-in to the plan; no string keyed here contains blame/loss framing ("you're behind", "lost", "you'll lose"), a mandate word, a countdown, an exclamation mark, or emoji.
- [ ] The ARB key contract (title + count-bearing body with `daysMissed`/`planLengthDays` placeholders) exists and is consumed via `l10n.*`; no hardcoded user-facing string or ASCII digit path; counts route through the locale numeral formatter with FSI/PDI isolation.
- [ ] This task builds no widget, no Today banner, no on-screen surface; the T06 sibling switch merely gains its controller wiring.
- [ ] No `DateTime.now()`, no networking symbol, no `flutter_local_notifications`/`timezone` import, and no engine/`loadBalance` import appears in any file this task adds (grep-verifiable).
- [ ] Turning the toggle off is one tap with no confirmation friction, and after the reconcile no catch-up note can fire (fully silenceable, no re-engagement).

## Tests

The independence, only-fires-on-signal, and banned-phrase suites are **written first**.

- `features/test/reminders/catch_up_note_toggle_test.dart` (unit) — **written first**: the flag defaults off (absent row → off, no row written by the read); `setCatchUpNoteEnabled(true)` commits before any republish is observable (recording repository + stream observer, per the T02/T03 pattern) and then triggers exactly one reconcile; flipping the catch-up toggle leaves `isEnabled` and the time byte-identical, and flipping the daily toggle leaves `isCatchUpNoteEnabled` untouched — independence pinned both directions.
- `features/test/reminders/catch_up_note_decision_test.dart` (unit) — the full truth table over (daily on/off × catch-up on/off × signal present/absent): the `catchUpNote` variant appears **only** for (catch-up on, signal present); toggle-off + backlog → the daily decision unchanged; the function is total (no throw on any combination) and its output carries the seeded `daysMissed`/`planLengthDays` integers through unchanged — proving no schedule or day-count is computed here.
- `features/test/reminders/catch_up_note_scheduling_test.dart` (unit) — against the T01 fake through the T05 reconciler: with catch-up on + signal present, exactly one `scheduleDaily` lands under the single fixed id with the note's localized title/body; a repeated reconcile is idempotent (no duplicate); the signal clearing or the toggle turning off converges the next rebuild to the daily-or-none state; both off → terminal `cancelAll`, zero fires.
- `features/test/reminders/catch_up_note_banned_phrase_test.dart` (unit) — runs the never-ship banned-phrase lint over every ARB value under this task's keys in fa/ckb/ar (once T10's values land; the gate is wired now and fails on a missing key): no "you're behind"/"N days lost"/"lose your hifz"/loss imagery, no mandate words, no "safe to drop"/"done"/"mastered", no `!`, no emoji — the assertion names C-042/C-041/C-043 as its trace.
- Grep guards (CI): no `DateTime.now()`, no engine/`loadBalance` import, no notification-plugin import, and no networking symbol in any file this task adds; no new member on `NotificationScheduler`.
- Offline guard: the suite runs under the throwing-`HttpOverrides` bootstrap (eng-write-dart-test) — no surface in this task opens a socket.
