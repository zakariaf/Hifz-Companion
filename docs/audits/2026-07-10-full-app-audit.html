A full refactor is not warranted. The engine math, persistence, backup format, and recite→grade spine are verified-solid. What's wrong is specific and listable: capabilities built but never wired, and the entire new-memorization loop missing. Your instinct about beginners was right — confirmed at blocker severity by seven independent auditors.

EnvironmentWhy it "didn't work" on this laptop — before any code finding

Two machine-local causes, one fixed, one confirmed as blocker F03

1. SDK (fixed). The migrated Flutter 3.24.3 couldn't resolve this repo at all. Now upgraded and pinned to 3.41.2 — CI parity, zero lockfile drift; the app builds and launches in the iOS simulator.

2. Muṣḥaf assets (F03). The 604 KFGQPC fonts + 3 data files are deliberately gitignored, the app is bundle-first (the downloader is dead code), and the fetch tool writes the wrong formats to the wrong directory. On any fresh checkout, onboarding dead-ends at Core setup with a Retry that can never succeed. Your old laptop worked because the files sat untracked in its working tree. Quick unblock: copy app/assets/quran/ from the old laptop.

FindingsBlockers — each survived adversarial verification

F01No new-memorization (sabaq) intake exists anywhere

No way to record "I memorized a new page" — ever. sabaqLines (required by PRD §7.8 and E04-T08's own acceptance criteria) has zero hits in the codebase; EngineConfig has no intake field; the card repository is read-only; grading a card-less page throws. A beginner can never start, and an existing ḥāfiẓ's schedule can never grow.

F02Onboarding hard-blocks a zero-juz beginner

The coverage step requires marking at least one juz as held (onboarding_view_model.dart:541) — no "I'm just starting" branch, no explanation, Continue permanently disabled. The only escape is lying, which seeds retrieval cards for unmemorized pages — explicitly wrong per the project's own science docs.

F03A from-source build dead-ends at Core setup

Assets gitignored by design + bundle-first runtime that never downloads + a broken fetch tool = no reproducible route from this repo to a runnable app. Fail-closed behavior working exactly as designed, with no path forward.

F04Profiles created in-app are permanently empty

profiles_controller.dart:57 seeds zero cards; no placement path exists for an existing profile (the re-onboarding controller designed for this is unreachable dead code). A teacher's students and a parent's child profiles sit on "all done" forever — nothing to sign off.

F05The Mutashābihāt trainer ships with no dataset

Loader, parser, tables, drill UI, and the engine's confusion-bump all built and tested — but no confusables data file exists in the repo, none is in the pinned manifest, and the loader has zero production callers. A headline nav tab is a permanent empty state.

FindingsMajor — confirmed

F06Mutashābihāt scheduling never fires in the live app

Sibling massing isn't injected into buildToday, the confusion D-bump has zero callers, swaps are never logged from real flows.

F07Cold start makes the entire held Quran due on day one

Up to 604 pages, all mandatory, permanent overflow — the dueFar union defeats the PRD's own "nobody can grade 604 pages on day one" calibration spread.

F08Graduation gates and the recent-juz window have no scheduling effect

phaseOf reads the stability band and ignores the stored track; recentWindow is never injected; the "near window (juz)" setting is inert.

F09"7-Manzil weekly khatm" never recites a contiguous manzil

Index-modulo scatter re-sorted weakest-first — unrecognizable as the manzil system to the audience this app serves. The juz map needed to fix it already exists, unused.

F10The missed-day catch-up plan is cosmetic

Accept/defer is local widget state; the engine's re-spread is computed and thrown away; the backlog stays fully due.

F11Dead controls: "new lines per day" and "pause new sabaq"

Persisted values that nothing reads — the user-facing face of F01. Reads as broken, not missing.

F12Active profile silently reverts to the first-created profile on relaunch

The app_meta.active_profile key is documented and specced (E16-T08) but never implemented — on a teacher device, reviews land in the wrong student's append-only sanad log.

F13Cross-device teacher↔student merge duplicates the student

Profiles get fresh UUIDs per device and merge keys on UUID — the union machinery is sound, the identity model that would make it useful is missing.

F14No single-student export

Only export-all exists; sharing one student's file discloses every other student's record. E16 and E17 each assigned this to the other.

F15No profile switcher or active-profile indicator anywhere in the chrome

Specced in E16-T09/T10, skipped — a teacher never sees whose log they're signing.

F16"Mark my memorized range" is absent

Coverage is write-once at onboarding, forever. E11 defers the tool to E13; E13 defers it back to E11.

F17"Start revision here" from the reader is absent

Recite is reachable only from a Today due-row; any page not due today is un-revisable on demand.

F18The prayer-critical retention tier is inert

The 0.97 floor for Fātiḥa, Mulk, Kahf etc. is honored by the math, but no card is ever marked prayer-critical — no seeding, no UI.

DiagnosisThe pattern behind the findings

Almost every serious finding is one of three shapes:

  • Engine-ready, app-unwired (F06, F08, F10, F18, F24, F25): the pure layer was built and tested to spec; the composition layer never passed the data or called the function.
  • Fell between two epics (F01's entry surface, F14, F16): each epic's EPIC.md defers ownership to the other; no task file ever owned it.
  • Silently resolved doc conflicts (F07, F09, F19): the PRD and task files disagree, and the code picked a side quietly — exactly what CLAUDE.md says must be surfaced instead.

None of this indicts the architecture. The fix is wiring, intake, and a handful of missing surfaces — ordered task work, not a rewrite.

PlanRecommended priority order

  1. F03 — a reproducible runnable build. Fix the asset fetch/normalize tooling. Nothing else can be verified end-to-end until a fresh clone runs.
  2. F01 + F02 + F11 + F04 — the new-memorization loop. Sabaq intake, a beginner path through onboarding, wire newLinesPerDay, placement for in-app profiles. One coherent epic; your core complaint.
  3. F07 — day-one calibration spread so a complete ḥāfiẓ doesn't face 604 mandatory pages on first launch.
  4. F05 + F06 — mutashābihāt data + wiring (scholar-reviewed dataset, massing, confusion logging).
  5. F12 + F15 + F14 + F13 — the teacher/halaqa loop (persist active profile, switcher chip, single-student export, cross-device identity).
  6. F09, F10, F16, F17, F18 — tradition-true manzil slicing, real catch-up persistence, coverage editing, reader hand-off, prayer-critical seeding.
